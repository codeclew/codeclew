# Codeclew 0.15.4 — larger portable evidence with bounded part handling

Export and transfer an existing retained snapshot without repeating capture or
recovery. Portable evidence supports 512 MiB of encoded parts per service, with
unchanged 2 MiB per-part, 4,096-part and 2,097,152-record protections. Formats 1.0
and 1.1 remain supported; an additional budget counts at most 67,108,864 JSON
values and object keys. Previously admitted 128 MiB envelopes remain within it.

```sh
clew docs evidence export --root DOCS_ROOT --service SERVICE_ID --snapshot SAVED_SNAPSHOT --output NEW_PACKAGE_DIRECTORY
clew docs evidence inspect --input NEW_PACKAGE_DIRECTORY
```

The writer spools bounded parts instead of retaining complete encoded and JSON
inventories. Loading constructs one typed evidence model. Import verifies copied
bytes again in a private stage before publishing the package and selected pointer.
A late input change refuses import and preserves the prior valid selection.
Raw paginated reads preserve original fields, record order and cursor ownership.

Inspection and reads still validate the entire package; small output pages do
not imply page-sized memory. Check and retained-cache hydration have separate
whole-service costs. Byte/node limits are finite resource guards, not a hard
RSS guarantee. Above them, saved-snapshot context and bounded Work remain local
analysis routes; repeating capture, refresh, recovery or a producer report does
not change an unchanged package limit.

Exact source/revision/digest bindings, trusted expectation requirements,
PARTIAL coverage, historical source authority and NON_CACHEABLE semantics remain
in force. Owned complete typed fixtures exercise 279 MB of portable evidence;
this does not claim a replay of the inaccessible private project. Supported
pilot packages remain macOS Apple Silicon, macOS Intel and Linux x86_64/WSL2.
