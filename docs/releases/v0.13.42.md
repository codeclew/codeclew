Codeclew 0.13.42 fixes compiler capture for larger Java fact streams and
Kotlin/Gradle projects with generated compilation inputs.

Java analyzer stdout is drained to a private temporary file and persisted in
ordered, hash-bound CAS chunks. Successful captures and warm reuse validate the
complete stream and its admitted source and classpath membership before
publishing a receipt. Existing successful raw-output receipts remain reusable. Fact publication uses
bounded CAS batches with unchanged payload identities and fact shards.
The total output limit is 512 MiB; the existing 256 KiB per-fact and 262,144-fact
limits remain in force. Exceeding a transport or fact limit reports
`RESOURCE_LIMIT`, separately from an unsuccessful Java compiler process.
Private compiler output remains available only through opt-in diagnostics.

Gradle model preparation now runs the selected compilation's declared
prerequisites, including generators attached through `compileKotlin.dependsOn`,
before reading its effective source inputs. It does not execute the selected
compiler task. Generated outputs stay in real, contained directories in the
disposable Kotlin workspace; source admission still rejects symbolic paths,
and cleanup verifies the original output-root identities. Project JDK selection and native build environment remain
separate from the JDK used to launch the Codeclew worker. Generated compiler
input hashes and facts are captured; generated-source text is still unavailable
to documentation source reads.

The owned regressions cover generated Kotlin sources with project JDK 25 and a
worker on JDK 21, and a natively compilable Java project whose compiler facts
exceed 64 MiB. These checks establish those supported cases; they do not assert
compatibility with every build plugin or an inaccessible private repository.
