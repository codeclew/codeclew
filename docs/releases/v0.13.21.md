# Codeclew v0.13.21 — readable processes and outgoing service calls

Process documentation can now show a declared external destination next to its
outgoing message, with the saved OpenAPI operation expanded in place. Addresses
retain their declaration source and an optional environment. They are inert
display data, not live requests or evidence of a deployed destination. An
external receiver needs no registered repository or checkout.

An outgoing contract is selected by an explicit saved contract-operation identity
or an exact, unique receiver binding. Missing and competing bindings remain
visible gaps; the caller's incoming API is never substituted. Retained authored
operations keep their original destination and contract when declarations change,
and report the change separately. Syntax-backed calls can use an exact retained
CALL observation without inventing a resolved target. See the
[outgoing service call guide](../operations/outgoing-service-calls.md).

Narrative input errors now identify safe field names and operation locations.
Invalid input is rejected as a whole, so valid sibling operations are not silently
applied. Diagnostics distinguish a retained authored narrative from generated
content. Bounded diagnostics redact unsafe names and never echo the entire input.

OpenAPI reading attempts the saved document's bounded path/operation structure
before assessing compatibility. Versions through 3.x are supported within this
reader's stated limits, without a patch-version allowlist. Missing or unfamiliar
version metadata produces explicit assumptions rather than an automatic rejection
of otherwise readable operations. This is not full OpenAPI or JSON Schema
validation, source-route verification, or runtime evidence.

Process authoring guidance now asks for useful business explanations while keeping
mandatory branches, loops and exits covered. The HTML reader removes an exact
generated explanation copy only when the same original text and evidence are
already visible beside the step. Distinct, authored and context-bearing text
remains visible. Markdown retains its main explanation outside collapsed
implementation details. See the
[readable process narrative guide](../operations/readable-process-narratives.md).

Existing capabilities remain included: core Kotlin 2.4.10 analysis, saved support
diagnostics and the read-only C# Roslyn preview. C# analysis requires .NET SDK 10+
and restored project inputs; candidate generation and managed source writes are
outside that preview.

The public pilot supports macOS Apple Silicon/Intel and Linux x86_64, including
Windows through WSL2. Linux requires glibc 2.35+ and Python 3.11+. The installer
verifies published checksums and does not compile Codeclew on the user's machine.

```sh
curl -fsSL https://codeclew.github.io/codeclew/install.sh | CODECLEW_PACKS= CODECLEW_VERSION=v0.13.21 sh
```

For an older installation still using the retired optional Kotlin 2.3 package,
follow the [installation and migration guide](../../README.md#install-on-macos-linux-or-windows-through-wsl2)
before upgrading.
