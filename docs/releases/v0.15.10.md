# Codeclew 0.15.10 — retained documentation and Gradle capture

The documentation runner accepts any measured author token count during
generation, repair and verification. It reports input, cached input and output
counters and the calculated uncached input plus output total. The runner enforces
wall time and repair limits and requires valid usage counters for acceptance.

Small HTTP services with complete retained source can use a structured inline
author turn. The runner assembles the pages, sequences and self-review and checks
them before export. Updates to existing checked documentation can reuse the
annotated originals and citation bindings.

The first HTTP step in a sequence can add an explanation after the exact method
and path. The check requires the original handler target. Markdown headings
receive distinct generated IDs when an explicit anchor already uses the same
name, preserving links from diagrams and navigation.

Java and Kotlin compiler capture can use declared Gradle project properties.
Set nonsecret string values in the owning checkout's `codeclew.yaml` under
`gradle.projectProps`. Codeclew passes each property as a separate `-P` argument.
Changed or removed properties invalidate active session reuse, and explicit
historical snapshots remain readable.

Release validation included a separate repaired Weather documentation example
with seven process narratives, linked handlers and contracts, and a process
catalogue. The checks covered retained documentation and rendered links.
Runtime deployment, broker delivery and production behavior were outside
that validation. Codeclew remains a public pilot.

Upgrade an existing supported installation with `clew upgrade`.
