# Codeclew 0.14.5 — actionable documentation diagnostics

Documentation proposals now report the complete set of uncovered mandatory FLOW
steps across operations. Read every diagnostics page to see the missing evidence,
required step kinds and next action together, instead of repairing one rejection
at a time. Large diagnostic tables use verified cache objects and the existing
proposal pagination. Other structural and evidence requirements remain enforced;
Codeclew does not generate missing process steps or prove semantic completeness.

For a known FLOW ID in a service Work, `docs work read` accepts a bounded exact
selection instead of requiring an inventory scan:

```json
{"query":{"kind":"FLOW","ids":["RETURNED_FLOW_ID"]}}
```

Select up to eight distinct IDs. Optional `expectedSnapshot` and
`expectedContextDigest` guards bind the lookup to the intended immutable Work.
Results retain their original records and Work-local references, normal page
budgets and recorded-read requirements. Missing, foreign or ambiguous identities
refuse. Exact selection uses indexes after full Work hydration and an initial
linear handle-index build; it does not promise constant command execution time.
Exact IDs currently support service Work only.

Invalid proposal and author inputs now include safe field paths, error categories,
expected and actual shapes, and repair guidance without echoing submitted values.
Selector, evidence and draft-input guidance identifies the next supported action.
The portable skill prioritizes delivered evidence and exact Work references,
documents a bounded fallback for 0.14.4, and preserves helper, boundary and failure
scope without switching to a controller root to reduce coverage requirements.
Same-Work SOURCE repeat reads and selector-specific cursors have regression checks.

These changes reduce avoidable evidence acquisition and proposal repair during
full-documentation work. They do not add a documentation generator or establish
the correctness of an authored explanation.

Install or upgrade:

```sh
clew upgrade
```

Refresh an installed Codeclew skill using the supported skill installation command
for your agent so its reading guidance matches this release.

Packages support macOS Apple Silicon/Intel and Linux x86_64, including Windows
through WSL2. Linux requires glibc 2.35+ and Python 3.11+. The supported installer
verifies published SHA-256 checksums and does not build Codeclew locally.
