# Codeclew v0.12.0 — retained documentation evidence and recovery (public pilot)

This release extends the documentation workflow with bounded access to retained
source, more evidence-linked explanations, and recovery for interrupted review
and publication work.

## Retained source and Java API context

- A prepared documentation Work can read an oversized retained SOURCE record in
  bounded parts from its exact saved snapshot. Complete, gap-free part receipts
  are required before that source can count as proposal evidence. Part reads do
  not acquire source evidence, and the Work reader still hydrates its saved
  Check in full.
- Fresh Work using `http-api-contract-v1` for one captured Java HTTP endpoint
  can include its direct declared parameter and return object-type declarations
  and retained source, when they are available in the same compilation scope
  and within the Work bounds. This is type preparation, not a complete API
  contract.
- Context lookup can follow bounded, unambiguous call relations in the selected
  source scope, including calls inside `try` blocks. Exception-flow analysis
  remains partial and requires source review.

## Documentation authoring and reading

- Process views can present evidence-linked behavior pseudocode and retain
  navigation to the corresponding source. The pseudocode summarizes supported
  source structure; it is not an execution trace. The reader improves catalog
  discovery and search-state preservation, and shows accepted entity-section
  diagrams beside their declarations.
- Author and reviewer jobs receive bounded, scoped evidence and completeness
  guidance. Claims must stay within delivered evidence, and review authority is
  labeled according to what was actually reviewed. These changes support
  human-reviewed documentation; they do not automatically produce a complete
  high-level documentation packet.
- Selected captures can be recovered from a stopped offline object-store export
  into an empty documentation root. Recovery verifies the selected saved object
  closure and preserves its source authority; it does not refresh source or
  restore unrelated Work, proposals, publications, or history.

## Recovery and authority

- Interrupted documentation runs persist their phases and accounting, reuse
  intact validated author/reviewer results, and can complete a still-current
  accepted publication without repeating saved work. Publication receipts bind
  the reviewed output before the working pointer changes. Recovery refuses
  mismatched or damaged state rather than finalizing it generically.
- A dispatched model call whose result was not saved may be retried within the
  original finite allowance. When provider usage is unknown, accounting keeps
  the maximum reservation; this is not an exactly-once or billing guarantee.
- Crash recovery releases abandoned writer ownership. Model approval labels
  identify the authority actually granted and do not imply additional human or
  runtime verification.

## Limits and qualification

Retained evidence is static evidence and may have recorded gaps or unverified
freshness. Source-part delivery covers only the exact saved SOURCE record;
manual reads do not bypass complete-context checks. Direct Java API preparation
does not establish inherited fields, validation activation, wire requiredness,
serialization, generic payloads, or a complete contract. Exception semantics,
dynamic behavior, and runtime effects remain outside the scoped call context.
An older export cannot recover relations that it never retained.

This remains a public pilot. The release asset matrix targets macOS arm64 and
x86_64 and Linux x86_64, with Kotlin 2.4.10 `core` as the default profile and an
optional Kotlin 2.3.0 read-only preview. End users need Python 3.11 or newer;
Linux requires glibc 2.35 or newer. Linux x86_64 also serves WSL2. Native Windows,
Linux ARM64, and musl are outside the support matrix. Follow the
[macOS and Linux release guide](../operations/releasing-macos.md) for
installation and platform smoke checks. Code signing, notarization, and
independent signature verification remain required before any general
availability claim.
