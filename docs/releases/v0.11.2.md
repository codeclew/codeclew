# Codeclew v0.11.2 — retained process flows and explicit release history

This release adds readable lifecycle flows from retained source evidence,
declarative state diagrams, and an explicit boundary between updating working
documentation and recording a released version.

## Process flows and state diagrams

- Process roots are addressable Work handles. Process views can show a
  pseudocode flow tree deepened from retained transformed source or a PlantUML
  activity diagram from compiler FLOW events. The source-syntax path uses
  bounded heuristics for supported constructs; these cues are not compiler FLOW
  facts. Unsupported or ambiguous syntax uses a conservative fallback and stays
  visible as a limitation.
- Lifecycle state diagrams come from author-declared
  `scenarios/<id>-states.yaml` files. A transition is rendered only when its
  operation or explicit evidence reference resolves unambiguously in the saved
  evidence. Every supplied evidence reference must resolve uniquely. When no
  references are supplied, an exact full symbol or unique method name may
  resolve the operation. The state machine remains an explicit author
  declaration; resolving an identity does not prove that a transition is
  semantically correct or occurs at runtime.
- State sidecars are captured with documentation inputs and affect the input
  digest. After editing a sidecar, `docs recompose --snapshot ORIGINAL_CAPTURE`
  refreshes the declaration snapshot offline using retained source evidence.
  Recomposition leaves the original capture intact and does not reindex source.
  Render the returned snapshot to see the updated declaration. Use `docs check`
  when source evidence itself needs acquisition or freshness checking.
- PlantUML is optional. Install `plantuml` on `PATH`, or set `PLANTUML_JAR` with
  Java available to render SVG. The sealed Codeclew runtime does not bundle or
  guarantee PlantUML. The flow tree and stored `.puml` source remain readable
  without it; SVG generation is opportunistic.

## Working documentation and released history

Default `docs render`, proposal publication, and Work jobs update working pages
and the stable `docs/index.html` entry point to the current internal bundle.
Only `docs render --publish` records an entry in released history. Internal
content bundles remain retained for evidence and optimistic-baseline checks.
This release does not add automatic cleanup of those bundles. Rendering a
compatible saved snapshot does not trigger source indexing.

## Limits

Compiler FLOW and retained source describe static source behavior, not deployed
execution. Source-syntax fallback recognizes only bounded supported syntax and
does not infer omitted callbacks, dynamic dispatch, or runtime effects. State
diagrams are author declarations checked against retained identities and are
not generated state machines or semantic verification.

## Reliability fixes

- Empty, compact, and Unicode source inputs no longer panic the flow parser.
  Comment and literal contents are excluded from syntax scans; unsupported
  shapes keep the conservative fallback.
- Sidecar detection uses the process-state schema, so ordinary scenario names
  ending in `-states` and service IDs such as `orders-states` remain visible.
  Only sidecars whose base scenario is captured contribute to the input digest.
- Process-tree navigation stays within the selected authored root. When SVG is
  unavailable, the reader keeps the available tree or PlantUML source visible.
- PlantUML labels are escaped for their rendering context, and the optional
  subprocess runs with a restrictive security profile and bounded time/output.
