Codeclew 0.13.35 adds canonical data-model reading and a portable documentation export.

Process guides can link a step to its canonical model, keep the original service account as technical context, and return to the same step with the selected field preserved. Model readers separate domain fields from their request, response, event and stored representations, with exact contract branches, usage statements and source evidence. Missing, stale and unresolved use remain distinct from a scoped negative finding. Only contracts referenced by a model or process are embedded in that reader. Data Flow opens with an all-fields comparison, including directly referenced model fields outside the selected investigation and unmapped contract leaves, labeled as unknown. Cell details preserve overview filters. HTML and MDX share a restrained type hierarchy and readable technical text.

`clew docs pages render --format docusaurus` exports a full publication as a deterministic Markdown/MDX project with pinned Docusaurus dependencies. Processes, service accounts, operations, HTTP contracts, models and source fragments have linked reading pages. Actor-directed diagrams preserve visible conditional branches; the complete original event stream and provenance remain available separately. Optional Data Flow readers preserve process context and work beneath a configured deployment base path. The generated README explains building, reviewing and deploying the project. Export does not publish a website.

The export shares repeated evidence through content-addressed JSON objects and checks that every complete native JSON document reconstructs exactly. Source identity includes its full recorded binding rather than text alone. Build-time reader packs group objects by their consumers without fetching unrelated evidence. Keep the MDX, inputs and normalized evidence in Git; dependency, build and transport-pack directories are generated outputs.

Historical SOURCE admission and maintenance comparison can also distinguish a changed whole-file Git blob from an unchanged selected source span. Unsupported, missing or conflicting whole-file evidence remains unknown. This is a correctness improvement; no performance improvement is claimed.

Retained evidence, declarations and editorial interpretations keep their existing review, freshness and runtime boundaries. Export does not establish application runtime conformance, delivery or ownership.
