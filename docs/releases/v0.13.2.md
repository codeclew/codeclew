# Codeclew v0.13.2 — endpoint fields and retained draft repair

## Endpoint documentation

- Under the current authoring contract, endpoint-context packets include the
  selected owner field declarations with their declared type, modifiers,
  annotations, source tokens and evidence. These fields remain separate from
  the static-and-final constants subset.
- Field declarations and initializer tokens are source evidence; they do not
  establish runtime values, initialization timing or deep immutability.

## Operation draft repair

- `docs work run --draft --repair-from-run <RUN_ID>` makes one explicit repair
  call for the latest retained invalid draft answer. The repair reuses the
  saved packet and answer and adds a freshly computed native validation error.
- The repair has its own run and reservation. Repeating the repair command or
  resuming with `--draft` continues that same run without another dispatch. A
  repair run cannot be repaired again; the selected source report, checkpoint
  and result remain intact.
- Retained authoring-contract 1.3 Work can replay its saved answer; this
  explicit repair is its only additional author-call path. Ordinary generation
  and `--new-run` remain blocked for that legacy Work.

## Public pilot scope and installation

Configured stdio author and repair execution requires macOS Seatbelt. Release
packages target macOS arm64 and x86_64, and Linux x86_64 (including WSL2, with
glibc 2.35 or newer); native Windows, Linux ARM64 and musl are outside the
package matrix. Linux author execution remains unqualified.

Draft outputs stay local as `DRAFT`, `UNREVIEWED` and `NOT_PUBLISHED`. Native
validation checks structure and evidence binding; it is not independent source
review or reader acceptance.

After v0.13.2 assets are published, install that pinned version with the
existing official installer:

```bash
curl -fsSL https://codeclew.github.io/codeclew/install.sh | CODECLEW_VERSION=v0.13.2 sh
```
