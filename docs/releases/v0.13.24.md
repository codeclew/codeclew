# Codeclew v0.13.24 — source-bound service processes and retained questions

This release adds source-bound ways to document service processes and ask focused questions about retained analysis. These features describe saved evidence; they do not establish live service behavior.

- Service documentation can record declared boundary contracts and receiving fragments. Frozen canonical process-page links bind a pinned service revision and published page digest to source and operation details, while reusing the existing page. They do not prove deployed routing or wire outcomes.
- `clew thread question` returns a bounded, read-only packet over a retained flow, with selector matches and optional control-flow observations. It preserves parent boundaries and marks selector matches as retained-flow evidence rather than complete program discovery. See the [question packet guide](../operations/question-packets.md). Bounded Java value evidence includes direct static-call transfers; Kotlin value evidence includes bounded immutable-local values. Guarded enum and property accessor attempts preserve compiler-resolved identities and source-conditional normal-completion prerequisites; setter dispatch and storage outcomes remain unknown.
- Internal process-graph Work can set `sourceDataMaxDepth` from 0 to 2 only with `sourceDataContext: true`. Depth zero retains the full root source and retained root data facts while keeping helper frontiers explicit. Omitting the field preserves the existing default. Expanding helper context stays on the retained snapshot; choosing a different depth requires a new immutable Work, without recapturing source. See the [snapshot and Work guide](../operations/docs-snapshot-store.md).
- The optional C# worker build is pinned to .NET SDK 10.0.401. Analyzing a project with the published worker still requires a .NET 10+ SDK on the host `PATH`; see the [build and platform requirements](../../README.md).
