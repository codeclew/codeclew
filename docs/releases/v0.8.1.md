# Codeclew 0.8.1 — offline documentation onboarding

Fresh documentation repositories now include local Codeclew help and runbooks
immediately after `clew docs init`. The guides explain relocation, adding services,
notes and comments, scenarios, entities, dataflows, requested detail and optimistic
input digests. Service-specific operational knowledge remains authored from source
and owner notes.

Every new publication includes cross-page navigation, guide pages, the Codeclew
favicon and the site's blue/cream palette. Historical snapshots retain their
original bytes; render again to obtain the new reader. Coverage and evidence now
shows optional compiler-provider status, mapped semantic declarations and example
facts separately from source syntax and meaning review.

The top-level help now lists the launcher-owned `skill` command. Transient process
inspection captures only its declared service scope and no longer hydrates saved
publication history. It remains read-only and does not run author/reviewer agents.

This remains a public pilot. GitLab integration and forty-service qualification
are deferred. Compiler evidence does not establish deployed routing, business
ownership or independently reviewed explanations.

```sh
clew upgrade
clew skill install --agent codex
clew docs init --root ./architecture --title 'Service documentation'
```

For an existing documentation repository, retain its original title when running
init to add missing starter guides, then use `clew docs render --root ./architecture`
to republish retained explanations with the new navigation.
