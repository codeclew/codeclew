# Codeclew 0.3.0 — JVM analysis and Spring computation roots

This release expands repository analysis and documentation support for Kotlin
and Java while preserving the existing exact compiler engines.

- Conditional Kotlin JVM analysis covers stable project versions 1.9.x through
  2.4.x with the packaged K2 engine. Kotlin 1.9 is explicitly reanalysed in
  language/API mode 2.0; this does not claim native 1.9 compiler equivalence.
- Java repository analysis accepts source releases 17+ up to the available JDK.
  Compiler qualification covers release 17 and 21.
- `clew entrypoints` enumerates annotation-declared Spring HTTP endpoints, Kafka
  listeners and scheduled jobs from sealed generations. It supports one or more
  sessions, or all members of a thread, with digest-bound pagination.
- Spring evidence includes resolved annotations, constants, composition and
  AliasFor, repeatable triggers, class mappings, KafkaHandler dispatch and
  inherited concrete implementations. Each root retains its full symbol,
  repository/revision/compilation and evidence reference for subsequent flow
  analysis. Runtime bean activation, property/SpEL values and programmatic
  registrations remain explicit verification obligations.
- The default core install can analyse a Kotlin 2.3.0 project without requiring
  its optional exact-engine pack. Installing that pack preserves the exact route.
- Mutation checks now bind the actual project compiler version separately from
  the analysis engine. Baseline analysis cannot acquire write authority by being
  analysed with K2 2.4.10. The qualified write contour remains Kotlin 2.4.10;
  broader 2.4.x write qualification is an explicit next milestone.
- The website explains the architecture, evidence transformations and extension
  points. The bundled skill selects the analysis profile from discovery and
  follows every catalogue page without treating runtime assumptions as facts.

Install or upgrade, then install the bundled skill:

```sh
curl -fsSL https://codeclew.github.io/codeclew/install.sh | sh
clew skill install
```

For an existing installation, run `clew upgrade` first. Reinstall an existing
older skill with `clew skill install --force` after reviewing the version update.

Read the [architecture](https://codeclew.github.io/codeclew/architecture.html)
and [implementation roadmap](https://github.com/codeclew/codeclew/blob/main/docs/plans/modular-jvm-roadmap.md).
