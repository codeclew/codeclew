Codeclew 0.13.45 fixes capture and Spring route evidence in Java and Kotlin.

Java Maven capture reads the effective compiler plugin and selected execution
release, including inherited configuration and active profiles. Evaluated Maven
properties remain defaults with their actual precedence, including testRelease.
A valid plugin-configured release no longer requires a convenience property.
Conflicting or unsupported compiler/toolchain configurations remain explicit errors.

Kotlin compiler annotation arrays preserve scalar, literal-array and arrayOf
forms without an extra vararg packing layer. Nested annotation values retain
their structure. Proven identical compiler handler registrations coalesce by
bean, callable and mapping; inherited registrations retain declaration witnesses.
Distinct controllers, overrides and unresolved registrations are not merged.

Java and Kotlin SOURCE_SYNTAX expose bounded Spring wildcard-import candidates.
They retain source-name and runtime-registration uncertainty; explicit conflicts
and known local shadows block qualification. Same-package shadowing is checked
after selected files are replayed, including unchanged file-cache hits. An unmatched
SOURCE route carries an explicit absence-unproven boundary.

Valid compact Kotlin class members no longer become partial solely because the
pinned grammar inserts a redundant missing class-member terminator before `}`.
Other parse errors and missing tokens still produce explicit partial capture;
source bytes and historical Work remain unchanged.

This fix does not add architecture policy verdicts or OpenAPI wire-conformance
validation. Route matching remains source mapping, not request/response proof.
