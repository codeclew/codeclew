# Codeclew 0.16.0 — one documentation pipeline

All new documentation and updates use authored originals or Markdown, followed
by compose, source binding and checked HTML finalization with the bundled
renderer. Service guides and cross-service processes share this route, including
Sources, diagrams, navigation and checked declaration components.

This release removes the alternative native documentation generators and their
public CLI entry points: native render/pages/DSL/proposal publication, status-page
refresh, the documentation author/reviewer coordinator and standalone answer
export/publication. Existing scripts invoking those commands need to migrate to
the authored-originals pipeline. The bundled skill, starter instructions and
active operations guides describe that route.

Saved source snapshots, Work, contracts, historical bindings, user originals,
source manifests and existing exports remain retained inputs. Evidence reads do
not regenerate old pages. When declaration component implementation identities
change, prepare a fresh ticket from the same saved selection, compare its exact
payload and HTML, and finalize a new baseline. The old-index conflict guard stays
strict; old tickets and exports remain historical artifacts.

Bounded SOURCE Q&A and saved-answer review remain available. `docs work run`
requires `--draft` and saves answer, evidence packet and audit JSON in a separate
run directory. It does not write HTML, Markdown or diagrams or overwrite previous
exports. Saved invocations, failed attempts and budget accounting remain durable.

Java compiler capture now handles colliding source positions in generated Lombok
value projections conservatively. Generated shapes that cannot preserve exact
node and parameter identities become unsupported value projections rather than
corrupting an input binding and rejecting an otherwise valid source capture.
Ordinary authored parameter bindings, source ranges and budget guards stay strict.

This release does not change the documented imported-library citation-helper or
external human-claim binding limitations. Supported public pilot packages remain
macOS Apple Silicon, macOS Intel and Linux x86_64, including WSL2, with existing
C# Roslyn support.
