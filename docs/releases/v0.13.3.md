# Codeclew v0.13.3 — static flow pages and external dependency evidence

## Static flow DSL documentation

- `docs dsl render` interprets supported Java builder-chain and operation-queue
  declarations from an original retained documentation snapshot using an
  explicit profile. One typed projection supplies MDX 3, standalone HTML,
  a local stylesheet, manifest and retained source appendix.
- Rendering needs no new capture, compiler, model call or network request.
  HTML remains readable without JavaScript. Existing generated filenames cause
  a conflict instead of overwriting user content.
- Profiles select exact source methods and declare effect classifications and
  reader labels. Local conditions, operation selections, mappings and opaque
  external calls remain distinct. Unsupported constructs produce local gaps.
  Declared callback or queue order does not prove runtime execution, delivery,
  engine activation or an actual incident cause.

This is a bounded static renderer, not automatic discovery of every business
process or a live question-answering interface. See the
[flow DSL guide](https://github.com/codeclew/codeclew/blob/v0.13.3/docs/operations/flow-dsl-documentation.md).

## External Java dependency evidence

- Resolved external type, method and constructor targets retain their
  compile-time identity, selected signature and exact admitted binary artifact
  origin. Artifact metadata distinguishes known, unavailable and ambiguous
  versions. Type references remain separate from method invocations.
- Available ordinary Maven source-classifier archives can supply exact source
  declarations after separate compiler-signature matching. Source provenance,
  content digests and source/body availability remain separate from binary
  resolution. Verification is bounded to 32 distinct source entries per
  compilation; unavailable, mismatched or unverified source stays explicit.
- Documentation evidence, endpoint context and supported portable evidence
  retain these bindings. Repeated immutable capture storage reuses its objects;
  imported or recovered evidence does not revalidate the current dependency.

Matching source signatures do not prove source-to-bytecode body equivalence.
No source is reconstructed from binaries, and dependency injection, concrete
runtime dispatch, remote HTTP contracts and execution remain unresolved. The
synthetic regression scope does not establish a complete corporate Maven or
dependency capture. See the
[dependency evidence guide](https://github.com/codeclew/codeclew/blob/v0.13.3/docs/operations/external-dependency-evidence.md).

## Failure diagnostics

- Compiler-index verification failures preserve the private worker-process
  diagnostic and retryability alongside the hash-only verification report.
  Use the supported sanitized summary when sharing diagnostics.
- Invalid explanation paragraphs identify the operation, paragraph and failed
  structural check without echoing private prose into the error message.

## Public pilot scope and installation

Packages target macOS arm64 and x86_64, and Linux x86_64 (including WSL2, with
glibc 2.35 or newer). Native Windows, Linux ARM64 and musl remain outside the
package matrix. The default `core` profile contains Kotlin 2.4.10; the optional
`kotlin23` profile adds the Kotlin 2.3.0 read-only preview. The installer verifies
SHA-256 checksums; Apple signing and notarization remain outside this pilot.

Configured stdio author and repair execution requires macOS Seatbelt. Linux
author execution remains unqualified. Draft outputs stay local as `DRAFT`,
`UNREVIEWED` and `NOT_PUBLISHED`; structural and evidence-binding validation does
not establish independent source review or reader acceptance.

After v0.13.3 assets are published, install the pinned version:

```bash
curl -fsSL https://codeclew.github.io/codeclew/install.sh | CODECLEW_VERSION=v0.13.3 sh
```
