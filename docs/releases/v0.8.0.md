# Codeclew 0.8.0 — local source documentation

This release adds a local documentation workflow for committed Python, Java and
Kotlin source, including projects that cannot currently build or load an optional
compiler provider. Register the service scope, capture evidence, prepare author
work, submit a constrained proposal, and publish with `docs proposal publish
--unassessed`. No API key, model gateway, GitLab runner or hosted renderer is
required for this path.

The offline reader includes service sections, source-derived interface cards,
optional OpenAPI input, declared cross-service processes and data-flow views,
protected human notes, exact source snapshots and publication history. Source
freshness and meaning review are distinct. Local publication records UNASSESSED;
a configured independent author/reviewer workflow can record reviewed meaning.
Neither status proves deployed behavior or resolves syntax-only call targets.

Exact revision updates reject late results, preserve prior explanations when
new evidence is unavailable, and expose gaps for unauthored or invalidated
content. Portable evidence can be transferred between local machines. Budget
ledgers survive work-cache loss. Bindings 1.3 share identical evidence inside one
snapshot and derive duplicate dependency digests from retained observations,
while preserving older fragment versions. Bindings 1.0, 1.1 and 1.2 remain readable.

Three local Kotlin service architecture reviews exercised the no-build authoring
path. This is not a claim of complete callable coverage, deployed-system
qualification, independently reviewed prose, 40-service capacity, or GitLab
integration. The larger workload and GitLab integration are deferred.

Install and refresh the portable skill:

```sh
curl -fsSL https://codeclew.github.io/codeclew/install.sh | CODECLEW_VERSION=v0.8.0 sh
clew skill install --agent codex
```

Start with the [local documentation guide](https://github.com/codeclew/codeclew/blob/v0.8.0/docs/operations/source-documentation.md).
The public pilot targets macOS arm64/x86_64 and Linux x86_64 (including WSL2).
Source-syntax documentation does not run application compilers; compiler-backed
analysis retains its existing toolchain and dependency requirements.
