# Codeclew 0.15.2 — shared catalogs from retained evidence

Build one shared catalog from explicitly selected documentation caches across
services and independent roots. Common external systems and domain terms have
canonical pages with links to each consuming service's local details. Addresses,
configuration and contracts stay with the service that uses them. Scoped terms
and DTO representations remain distinct from shared domain concepts.

The bundled skill provides collection, explicit identity decisions, incremental
updates and a concrete five-service export runbook. Unchanged definitions and
originals can be reused without recapturing source. Existing decisions are
preserved; proposals cannot silently replace them. Matching names, IDs or hosts
do not establish shared identity.

Declared records and explicitly selected approved historical glossaries now use
typed citations through the existing authored-originals, compose, bind and checked
HTML pipeline. Sources preserves their actual origin separately from code
excerpts. Saved glossary entries keep their original uncertainty and snapshot
applicability; they do not automatically become shared definitions or SOURCE proof.

Multi-root binding verifies each citation through its caller-selected owning
root, including when different roots use the same service ID. The renderer links
canonical systems, local uses, scoped terms and representations without requiring
an external system to masquerade as a captured service. Ordinary exports and
existing cross-service process navigation retain their previous format.

This patch does not infer runtime behavior, repair missing definitions or create
an approved glossary when no saved approved answer exists. Public pilot platforms
remain macOS Apple Silicon, macOS Intel and Linux x86_64, including WSL2.
