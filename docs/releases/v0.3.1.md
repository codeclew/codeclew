# Codeclew 0.3.1 — Spring Maven analysis in working repositories

This release fixes issues exposed by a real Kotlin 2.3 / Java 21 Spring Maven
pilot and makes analysis failures easier to act on.

- Repository discovery accepts Maven installed through package-manager symlinks
  and agrees with task readiness about launcher availability.
- `--committed` explicitly selects committed HEAD for read-only analysis when
  local edits exist. The snapshot excludes those edits, preserves the checkout,
  and cannot relax mutation readiness.
- The core K2 runtime includes matching official all-open and no-arg compiler
  plugins. Spring/JPA presets and custom options are preserved during baseline
  analysis. Unknown plugins remain unqualified.
- Baseline analysis preserves the qualified
  `-Xannotation-default-target=param-property` option. Other unqualified options
  remain explicit blockers.
- Constructors of enum entries with overridden bodies have consistent compiler
  and JVM owner identities. The evidence validator retains its strict checks.
- Function types distinguish a nullable return value from a nullable function.
  Ordinary callbacks such as `(T?) -> T?` no longer fail evidence validation.
- Exact navigation accepts the Kotlin symbol identities returned by the Spring
  catalogue, including JVM signatures that distinguish overloads. Short names
  remain file-scoped and ambiguous matches are refused. New contexts use the
  updated query index; reopen an analysis context after upgrading.
- Plugin failures no longer trigger an unavailable optional engine and hide the
  original cause.
- Maven and Gradle failures identify known dependency, authentication, TLS, JDK
  and compilation causes with a next action. Internal evidence failures explain
  the Codeclew validation stage and retain safe hashes without copying compiler
  source lines or private paths into diagnostics.

Kotlin baseline analysis remains conditional. Mutation qualification remains
Kotlin 2.4.10, and runtime activation of discovered Spring handlers still
requires environment evidence.

```sh
clew upgrade
clew skill install --force
```
