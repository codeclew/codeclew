# Codeclew 0.6.0 — Kotlin service documentation

Durable documentation now supports Kotlin/JVM Maven and Gradle projects from
1.9 through the supported 2.4 line, alongside Java 17+. Named scenarios can
span up to eight services and include engineer-declared HTTP and Kafka links.
The overview can contain more services; each service selects one compilation.

Kotlin compiler evidence retains Spring HTTP handlers, Kafka listeners,
scheduled roots, outbound calls and branch-aware computation steps. Versioned
workers preserve project and analyzer identities. Kotlin 1.9 inputs use the
analyzer's language/API 2.0 mode, with that compatibility boundary reported.
Declared links and dynamic topic expressions remain explicit uncertainties;
matching topics do not prove broker delivery or deployed configuration.

Agent-authored domain explanations can link individual paragraphs to diagram
steps and their source evidence. The offline site renders these explanations
beside navigable diagrams. Short business overviews and declared service maps
appear first; detailed implementation commentary and large source diagrams open
on demand. Source changes invalidate affected explanations.
Archived overview pages now resolve links within their own immutable bundle.

For projects without OpenAPI, agents can document HTTP, Kafka and payload
contracts using source-bound rows. Every row retains its own dependencies and
source references, so a DTO or handler change invalidates the affected contract.
These descriptions are explicitly separate from published OpenAPI and do not
turn Kotlin nullability into a claim about required JSON fields. The `docs context
--symbol` option retrieves exact DTO declarations within the same workflow.

Validation covers Kotlin control flow and Spring extraction on the 2.1, 2.3 and
2.4 workers, a native Kotlin 1.9 Maven fixture, eight-service composition,
narrative bindings, freshness and the existing Java documentation workflow.
These checks establish the tested static behavior; they do not establish
external model quality or runtime execution of a documented scenario.

See the [documentation workflow](https://github.com/codeclew/codeclew/blob/v0.6.0/skills/codeclew/references/service-documentation.md)
and [Kotlin fixture](https://github.com/codeclew/codeclew/tree/v0.6.0/fixtures/durable-docs-kotlin).

Install the published package:

```sh
curl -fsSL https://codeclew.github.io/codeclew/install.sh | CODECLEW_VERSION=v0.6.0 sh
clew skill install --agent codex
```

For offline installation, download the release's `install.sh`, its checksum,
the archive for the target platform and its checksum into one directory:

```sh
CODECLEW_VERSION=v0.6.0 CODECLEW_ASSET_DIR="$PWD" sh ./install.sh
```

macOS arm64/x86_64 and Linux x86_64 packages retain the existing platform and
public-pilot mutation requirements. The default runtime includes Kotlin 2.4.10;
the optional Kotlin 2.3 pack remains available. Project dependencies must be
available through the environment's build caches or configured mirrors.
