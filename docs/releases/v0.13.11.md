# Codeclew v0.13.11 — ask for the saved evidence you need

## Grouped context decisions for authors and reviewers

New operation Work can explicitly select
`codeclew-operation-draft-authoring/1.6` with `endpoint-context-v3` or a
`process-graph-v1` question. The initial packet keeps the complete existing
semantic context, source identities and gaps. An author can answer immediately
or request a group of native references, exact symbols or queries. The host
delivers complete content pages and contiguous source parts from the retained
snapshot before the next decision. A navigation result becomes citable only
after its source record is selected. Missing or ambiguous symbols return lookup
feedback.

The execution configuration uses schema 1.1 and a positive, caller-selected
`authorCalls`. Independent review has its own schema 1.1 configuration and
`reviewerCalls`. Both roles receive their configured and remaining call counts.
The host reserves the entire finite path before execution. Reservations are
maximum admitted usage, not actual model usage.

Reviewer expansions form a separate evidence context bound by
`reviewContextDigest`; they never rewrite the author's saved packet or answer.
Approved export validates the exact saved inputs, responses, context and native
receipts. Existing default authoring contracts and execution schema 1.0 retain
their behavior. See the [configuration and recovery guide](../operations/docs-snapshot-store.md#opt-in-section-author-contract).

## Recover without silently repeating a model call

Replay resumes an interrupted grouped delivery and validates its saved source
prefixes. Terminal replay can settle an interrupted accounting tail under the
original configuration, preserving the selected checkpoint and saved responses.
Completed accounting replay performs no writes or model calls.

An uncertain invocation is not automatically dispatched again. An explicit new
author run requires a terminal unsuccessful run and settled accounting. The new
author mode does not yet support repair selectors. An explicit uncertain-review
retry uses a new empty account, preserves the failed invocation and accounting,
and starts from its exact completed evidence context. It cannot replace a saved
verdict, an invalid completed result or an unsuccessful retry child. No refund
or provider cancellation is implied.

## Keep local reader navigation coherent

On the next publication, untouched generated Help and Runbooks pages link to the
current bundle along with Home and Browse. Digest-verified ownership markers
protect generated guide updates; edited guide content is preserved. Immutable
historical publication bytes are not rewritten.

The publication runbook opens the reader written by proposal publication. A
separate projection first recomposes the original source snapshot with accepted
explanations, then renders the returned snapshot; it no longer suggests rendering
the earlier capture immediately after publication.

## Scope and limits

Grouped delivery, exact result binding, interruption recovery, finite-budget
exhaustion, accounting recovery and reviewer retry have focused regression
coverage. This feature does not establish a token saving: the initial semantic
packet remains complete, and every follow-up model call contributes to usage.
Model review assesses the saved evidence, independently from current checkout
freshness and runtime behavior. The configured operation author/reviewer driver
requires its documented platform isolation and explicit finite configuration.
Local draft export alone does not publish a document.
