# Codeclew 0.15.15

Kotlin documentation checks now use less JVM heap while indexing large
compilations. The worker streams compiler observations and large index responses
within the existing transport limits. Documentation flow can attach to a
compiler declaration with incomplete type attributes when the compilation, file,
symbol, and source range identify exactly one declaration. The documentation
still reports the missing attributes as a coverage boundary.

Native FIR capture supports the qualified Kotlin 2.2.21 kapt and Spring
all-open configuration on Gradle 8.14.1 with JDK 21. The Kotlin 2.4.21
regression on Gradle 9.4.1 and JDK 25 also checks links to Java generated by
kapt and by a separate source producer.

The default offline support bundle can report which worker phase failed,
distinguish JVM heap exhaustion from transport failures, and show which part of
a Kotlin documentation flow owner binding could not be verified. These
diagnostics omit source text, paths, and symbol names.

See [Gradle capture settings](https://github.com/codeclew/codeclew/blob/v0.15.15/docs/operations/gradle-project-properties.md)
and the [installation guide](https://codeclew.github.io/codeclew/). Existing
installations can update with `clew upgrade`.
