# Codeclew 0.15.6 — Java capture and bounded documentation

Java compiler capture retains parameter reads in compact record constructors,
including reads in validation branches and thrown exceptions. These parameters
have no explicit declaration span in javac; their evidence now links the actual
constructor-body access to the ordered record component and constructor slot.
No explicit parameter declaration is fabricated.

```sh
clew upgrade
```

After upgrading, repeat the existing `clew docs check` command with the same
documentation root, service selection and compiler profile. Existing failed
captures are preserved; this fix requires a new capture. It does not repair
missing dependencies or establish success for an inaccessible private repository.

The new relationship is validated on capture and in portable evidence against
the canonical constructor, complete component inventory, compilation scope and
retained source. Contradictory unavailable field or ordinary parameter evidence
remains an error. Source profiles and older snapshots are unchanged.

Worker builds also use their pinned SDK directory when a newer .NET SDK is
installed alongside it, preserving the trusted distribution checks.

Java array constructor and clone references no longer crash capture when javac
returns no module for its synthetic array owner. The actual reference and source
location are retained with an explicit unknown-origin boundary. Synthetic array
targets remain distinct from a source or dependency class named `Array`; no
binary or source attachment is inferred from the missing module.

Guided documentation runs now freeze the retained scope and source inputs before
authoring, prepare compact source views with original citation handles, and run
the required diagram, process-search, link and source checks themselves. Missing
pages, interrupted generation, failed checks or unavailable usage counters block
ready-output promotion. The author records a bidirectional scope and claim review;
mechanical checks do not establish semantic truth or runtime behavior.

The primary model budget counts uncached input plus output. Cached input and
reasoning subsets remain separately visible, and failed attempts are preserved.
A compact review template derives redundant bookkeeping while leaving semantic
dispositions, discovered starts and unknowns for the author to assess. Process
search checks match the renderer's start, end, internal-service and outcome filters.
