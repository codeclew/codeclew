# Codeclew 0.15.9 — bounded Java fact processing and live capture progress

Large selected Java services now admit exact matching-domain fact references,
hydrate verified CAS payloads in bounded units and project all compilations through
one temporary index. The former service-wide 524,288-fact / 256-MiB aggregate no
longer limits this Java path. Compilation membership, repeated scoped occurrences,
global annotation and symbol interpretation, variable/body evidence and cross-module
relations remain part of the same projection. Individual fact payloads retain an
8-MiB limit. Source text, compact indexes and final evidence still grow with scope;
this is not a constant-total-memory guarantee. Other language capture limits remain.

Live stderr distinguishes native compilation, model extraction, compiler analysis,
reference admission, hydration, projection, serialization and storage. Compatible
progress/1.0 events add measured counters and terminal causes without exposing
source/module names or paths. Heartbeat indicates liveness only. Stdout remains
final result JSON, and UNRESOLVED Check completion is reported as failed progress.

Saved Check and default offline support retain closed numeric fact-budget and raw
compiler-output diagnostics, preserving prefix versus planned totals and actual
compiler, integrity, storage or oversized-unit causes. Raw compiler-output bytes,
CAS payload bytes and stored-object budgets remain separate units. Older failures
cannot acquire measurements that were never recorded.

These changes are qualified on owned fixtures and exact official packages. They
do not establish success for an inaccessible working repository or for Weather
authoring. No author workflow changes are included.

Upgrade an existing supported installation with `clew upgrade`.
