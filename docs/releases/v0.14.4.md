# Codeclew 0.14.4 — SOURCE reads with retained process context

Retained Work containing published operations and gaps can now prepare selected
SOURCE fragments through the ordinary evidence helpers. Previously, batch
acquisition incorrectly assumed that a reference selection contained only its
SOURCE rows and service coverage. Valid retained context could cause
`SOURCE_BATCH_NO_PROGRESS` or `SOURCE_BATCH_MEMBERSHIP_CHANGED` after native
delivery, leaving no verified fragments.

The helpers now request the explicit `SOURCE_ROWS` selection projection. Native
pages label this projection and return the original service coverage and exact
registered SOURCE rows without repeating retained operations and gaps for every
group. Ordinary context reads preserve their rows and behavior. Projection
identity participates in cursor binding, page receipts and recorded selections;
cross-projection cursors and inconsistent receipt/page projection refuse.

Citation validation also accepts complete historical mixed-context reference
pages using their actual totals, while checking every selected fragment and
preserving native context unchanged. Missing members, corrupt proofs and
incomplete continuations refuse. Genuine native size omissions retain the
existing source-part recovery. SOURCE_NATIVE and whole-file admission remain
separate. A selected SOURCE projection proves fragment delivery; read retained
processes and gaps separately before describing whole-service behavior.

Public regressions cover published retained operations, small continuation pages,
source-part recovery, corruption controls and bounded multi-file acquisition.
These transport checks establish neither semantic documentation quality nor
compiler/runtime conformance.

Install or upgrade:

```sh
clew upgrade
```

Packages support macOS Apple Silicon/Intel and Linux x86_64, including Windows
through WSL2. Linux requires glibc 2.35+ and Python 3.11+. The supported installer
verifies published SHA-256 checksums and does not build Codeclew locally.
