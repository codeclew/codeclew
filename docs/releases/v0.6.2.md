# Codeclew 0.6.2 — Maven admission and worker failure diagnostics

Java/Maven analysis now checks the selected module's resolved build directories
from its effective POM. Spring Boot `repackage` output directories such as
`web-build` no longer trigger the restriction on compiler output directories.
Inherited settings and active profiles participate in the check. Nonstandard
source, classes, or build directories and an active Maven toolchains plugin
remain outside this analysis profile; failures identify the relevant build
field without exposing its private value.

Kotlin worker transport failures now report the protocol stage and the observed
process exit code or signal, when available. They retain at most the last 64 KiB
of stderr in a private mode-0600 file and include the verified runtime/worker
identity in local diagnostic evidence. Capture is bounded and drains stderr
without blocking the protocol. Raw stderr is not printed or shared, and a
capture failure does not replace the original error.

`docs check` preserves these worker diagnostics for unresolved services.
`support summarize` now accepts documentation checks and their paginated
results, exporting only failure counts, typed codes, and safe process details.
Page summaries explicitly describe partial counts; service names, paths,
runtime identities, stderr, and source content remain private.

The worker's fixed JVM limits and language support profiles are unchanged.
An EOF or SIGKILL is not classified as OOM, and this release does not claim to
resolve a worker crash whose underlying cause has not yet been established.

Install the published package:

```sh
curl -fsSL https://codeclew.github.io/codeclew/install.sh | CODECLEW_VERSION=v0.6.2 sh
clew skill install --agent codex
```
