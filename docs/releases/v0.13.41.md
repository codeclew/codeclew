Codeclew 0.13.41 adds bounded Java/Spring thread preparation for compiler and
SOURCE_SYNTAX documentation captures in the public pilot.

Ordinary service Work can inventory the selected input files, excluded files,
public entrypoints and unsupported source surfaces through `THREAD_INVENTORY`.
`THREAD_CONTEXT` follows retained compiler declarations or offers explicit
source-name navigation candidates beyond the controller. Bodies, calls, writes,
failures, deferred work, provider limits and budget cuts remain separate
obligations. Source-name candidates never become resolved execution edges.

`docs work assess-thread` records explanations backed by complete source reads;
`docs work thread-status` resumes their progress independently of pagination and
publication. A controller read cannot account for downstream code. Source-local
provider limits belong to their own thread, while missing evidence, unknown
global limits and budget cuts remain open. Accounts do not establish semantic
approval, runtime dispatch, durable storage or delivery.

Rows omitted by a small Work byte budget provide an explicit recovery request
for a larger Work against the same saved snapshot. Check `omitted` on every
page, even when `nextCursor` is null.

The owned Java/Spring regression covers five direct HTTP roots plus inherited
and composed surfaces, validation before a try/catch, state changes, external
calls, interface/overload ambiguity and deferred callbacks. Unsupported surfaces
and partial captures remain visible; this release does not claim universal
framework discovery or full runtime closure.

See [thread preparation](../../skills/codeclew/references/thread-preparation.md)
for the supported Work queries, assessment format and capture guidance.
