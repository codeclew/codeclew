# Codeclew 0.4.1 — WSL2 installation and indexed Java documentation

The public pilot now includes prebuilt Linux x86_64 bundles for both the default
`core` profile and the optional `kotlin23` profile. Windows x64 users can install
and run Codeclew inside WSL2. macOS Apple Silicon and Intel bundles remain
available.

Java Maven analysis now accepts a non-executable shell wrapper and caller-local
Maven settings without requiring a preparatory configuration commit. The Java
index can deliver exact retained source for documentation, including projects
that compile generated dependencies.

```sh
curl -fsSL https://codeclew.github.io/codeclew/install.sh | sh
```

Run this command in the WSL2 Linux shell. Linux requires glibc 2.35+, Python
3.11+, Git, and curl, with JDK 21 for Kotlin project analysis. Keep installation,
managed state, and repositories in the Linux filesystem. Native Windows shells,
Linux ARM64, and musl distributions are outside the release matrix.

- The installer selects the Linux archive automatically and checks glibc before
  downloading it. SHA-256 verification uses Python and does not require Perl or
  `shasum`.
- Offline installation, `clew upgrade`, and Kotlin pack installation/removal use
  the same platform selection. Existing macOS asset names are unchanged.
- Release builds install each produced profile from its archive into isolated
  directories and check the installed CLI version and runtime capabilities.
  The core archive also runs branch and annotated-tag navigation checks.
- Publication waits for all three platform builds and verifies the checksums
  of all six archives.

For Java Maven projects, use `--maven-settings /path/to/settings.xml` or a local
`codeclew.yaml`:

```yaml
version: 1
maven:
  settings: ../settings.xml
```

The configuration and settings can remain outside committed source. Doctor and
extraction share the wrapper selection, and settings remain scoped to the
session. Java source spans now include Unicode-safe line/byte positions, so
`nav query` and `nav expand --source` can supply indexed declarations directly.
The bundled skill explains this workflow and the limits of incomplete indexes.

A public Spring Petclinic REST check compiled for Java 17 on JDK 21, inspected
397 class/method records, returned 36 HTTP entries, and delivered exact retained
`OwnerRestController` source. The example and evidence bindings are in
[the Java validation note](https://github.com/codeclew/codeclew/blob/v0.4.1/docs/product/validation/java17-maven-index.md).
This does not establish execution on an actual JDK 17 installation or behavior
of the unavailable private project from the original feedback. The new wrapper
and settings workflow applies to Java Maven analysis. Java remains read-only;
generated declarations are outside the source index, and inherited handler
source can be unavailable, with explicit `PARTIAL/UNSURE` obligations.

For offline WSL2 installation, download `install.sh`, `install.sh.sha256`,
`codeclew-linux-x86_64.tar.gz`, and `codeclew-linux-x86_64.tar.gz.sha256` from this
release into one directory, then run:

```sh
CODECLEW_VERSION=v0.4.1 CODECLEW_ASSET_DIR="$PWD" sh ./install.sh
```

Use the `codeclew-kotlin23-linux-x86_64.tar.gz` archive/checksum pair and
`CODECLEW_PACKS=kotlin23` for the optional Kotlin 2.3.0 preview. Existing installed
launchers can update with `clew upgrade`.

This is a public pilot. Hosted Linux checks do not constitute a WSL2-specific
filesystem qualification. Language evidence and mutation admission retain their
existing coverage limits.
