# Codeclew 0.5.0 — durable service documentation

Codeclew can maintain a separate documentation repository containing an overview,
a page for each registered Java service, and named interaction scenarios. The
new `clew docs` commands initialize the repository, register services, bind local
checkouts, record engineer-declared HTTP relationships, provide bounded authoring
context, check freshness and render an offline documentation site.

Each documented operation combines a plain-language explanation, a source-bound
sequence diagram, contract facts and explicit boundaries. Selecting a diagram
step opens the retained source. Generated bundles include HTML, JSON, Markdown,
Mermaid and portable fragment dependencies. The renderer is service-neutral;
the packaged skill explains full-entrypoint coverage, branch-preserving authoring
and recovery without earlier conversations or session IDs. Narratives are authored
by the user's agent; Codeclew does not require a hosted model or API key.

Freshness distinguishes changed methods, routes, contracts and declarations from
line-only source movement. A receiver route change marks its interaction card,
affected scenario edges and contract fragments. Unaffected explanations can be
retained; stale explanations require reviewed replacement input. Missing source
or history remains unresolved. Manual notes outside generated output are preserved.

The first scope is Java 17+ Maven/Gradle read-only analysis, one compilation per
service and at most two services in an individual scenario. HTTP observation
supports resolved Spring RestTemplate calls with literal paths and `@Value`
destination keys. Versioned OpenAPI 3.0 local references and constraints are
available as separate contract evidence. Dynamic routing, deployed configuration,
DTO wire compatibility, gateway behavior and unsupported control flow are explicit
boundaries. A declared interaction never becomes compiler or runtime proof.

See the [walkthrough](https://github.com/codeclew/codeclew/blob/v0.5.0/skills/codeclew/references/service-documentation.md)
and [executable fixture](https://github.com/codeclew/codeclew/tree/v0.5.0/fixtures/durable-docs).
The fixture checks both services with native Maven/javac, complete conditional
narratives, selective freshness and successful recovery using a fresh home.
It does not establish the quality of any particular external model.

For a protected Linux/WSL2 environment, transfer `install.sh`, its checksum,
`codeclew-linux-x86_64.tar.gz` and its checksum from this release to one directory:

```sh
CODECLEW_VERSION=v0.5.0 CODECLEW_ASSET_DIR="$PWD" sh ./install.sh
clew skill install --agent codex
```

macOS uses the corresponding arm64 or x86_64 archive. Offline installation
contains the runtime and bundled skill; target project dependencies must still
be available through the environment's Maven/Gradle cache or repository mirror.
The release retains the existing macOS and Linux platform requirements and
public-pilot language/mutation limits.
