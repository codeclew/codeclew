# Codeclew 0.14.3 — batched retained SOURCE preparation

Ordinary `read-files` and `read-sources` evidence helpers now acquire complete
retained SOURCE rows in bounded batches. File-navigation pages and SOURCE
reference groups share native invocations across files, including fragment-only
Work without whole-file proof. The new `docs work read-batch` serves up to 64
ordinary SOURCE page selections after loading immutable Work once. It preserves
page limits, cursor bindings, recorded page receipts and explicit local errors;
the read ledger commits atomically before successful output is returned.

Citation validation accepts exact native batch-row proofs alongside existing
source-part proofs. Original source IDs/references, text and record digests,
revision, authority, occurrence and citation bindings remain intact. Bulk stdout
is retained unchanged with exact page pointers. Proof caches are limited to one
validation operation and its Work, snapshot and receipt identities. Native size
omissions use the established part recovery; missing or changed evidence refuses.

No source recapture or source-runtime fallback is required. Fragment grouping
does not prove whole-file capture, compiler completeness or runtime behavior.
Genuine registered `SOURCE_NATIVE` evidence retains its separate supported path.
The helper keeps explicit controls for bounded legacy comparisons and documents
measurement of metadata, source acquisition, recovery and proof validation before
a large preparation. Throughput depends on retained evidence and Work capacity;
reduced invocation counts alone do not establish practical elapsed time.

This public pilot supports macOS Apple Silicon/Intel and Linux x86_64, including
Windows through WSL2. Linux requires glibc 2.35+ and Python 3.11+. Keep WSL2 state,
installation and repositories in the Linux filesystem. The installer verifies
published SHA-256 checksums and does not compile Codeclew locally.

Install or upgrade:

```sh
curl -fsSL https://codeclew.github.io/codeclew/install.sh | sh
```
