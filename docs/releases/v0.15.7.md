# Codeclew 0.15.7 — large documentation captures

Large source and contract maps are now saved as indexed immutable parts instead
of one serialized object. Captures can exceed the 128 MiB per-object limit while
preserving every record, revision, compilation identity and cross-module link.
Selected snapshot/context reads, retained evidence export/import and recovery
from a stopped SQLite export resolve the same complete parts. Small maps keep
their existing format, and supported 0.15.6 snapshots remain readable.

After upgrading with `clew upgrade`, repeat the original `clew docs check` with
the same service and source scope. Previously failed captures stay preserved;
the fix needs a new capture and does not repair unavailable dependencies or prove
success for an inaccessible repository.

An individual serialized record still has a 128 MiB limit. Its failure now shows
the object schema, storage stage, actual bytes and limit in public diagnostics,
UNRESOLVED summaries and support metadata. Such a record needs a bounded producer
representation; retrying unchanged input or dropping modules does not fix it.
Collect existing metadata without recapture:

```sh
clew support collect --root /absolute/docs-root --output /absolute/new-bundle
```

The source-free diagnostic omits source text, record IDs and local paths. Missing,
corrupt or mismatched parts fail explicitly. Capture storage changes do not
upgrade syntax coverage into compiler or runtime proof. Portable evidence packages
retain their separate per-row and total transport limits.
