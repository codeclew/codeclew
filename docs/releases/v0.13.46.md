Codeclew 0.13.46 fixes Kotlin/Gradle compiler capture that could fail semantic
verification even when a clean native build resolved a generated Java type.

The selected Kotlin compilation's Java source files now reach the analyzer as
separate analysis inputs. This includes generated Java registered through declared
Gradle source/task providers. Model extraction runs the selected compilation's
prerequisites, so a local prebuild is unnecessary.

Java input membership and bytes participate in semantic input authority and
freshness. Changing the generated API requires new matching semantics; missing
or invalid output fails verification instead of reusing older successful facts.
The Kotlin declaration index remains scoped to Kotlin files, and selected main/test
boundaries and project-versus-analyzer JDK authority are retained.

Mixed Java/Kotlin analysis uses the direct compiler backend and reports
`KOTLIN_JAVA_INPUTS_DISABLE_INCREMENTAL_BACKEND`. SOURCE remains an explicit
syntax profile: it does not run generators or acquire compiler authority after a
compiler failure. Unretained generated code is not invented.

The owned regression uses Kotlin 2.3.21, Gradle 9.6.1 and project JDK 25 with the
packaged Kotlin 2.4.10 analyzer on JDK 21. It demonstrates the input-propagation
fix; confirmation against a private service still requires that service's own
working environment.
