# Codeclew 0.4.0 — saved-change analysis and faster index reads

This release combines analysis of saved working-tree edits, retained visual
change explanations, and indexing improvements.

- `nav query` and `context open` accept `--working-tree` for immutable read-only
  analysis of saved tracked and eligible untracked source files. Later edits
  cannot change retained evidence; mutation still requires its own admission.
- `change inspect` compares the selected working-tree snapshot with committed
  HEAD and retains bounded before/after source, declaration changes, and direct
  Kotlin consequences. Related tests are evidence to inspect, not proof of
  sufficient coverage.
- Retained HTML reports connect changes and consequences to exact source and
  freshness checks. The website includes source-bound navigation and
  working-tree examples produced through Codeclew dogfooding.
- Ready-context reads use a derived paged CAS index instead of materializing
  the whole catalog. Pages and payloads remain hash-checked; canonical JSON and
  the journal retain recovery authority. Ordered journal validation avoids
  repeated page reads when the bounded cache fills.
- Initial indexing reuses project-model inventories and compiler fact lookup
  tables, batches Git metadata reads, streams generation facts, and bounds
  per-term query postings. Overflow remains explicit in query completeness.
- Exact Kotlin/JVM identities retain overload-safe lookup alongside bounded
  lexical search. New contexts use query-index schema 6; open a new analysis
  context after upgrading.
- Local untracked notes do not block committed-source admission. Working-tree
  analysis includes eligible saved source only when explicitly selected, and
  publication refuses to overwrite unrelated untracked files.

Before integration, three warm trials per case measured request medians of
202 ms for the production Kotlin corpus, 171 ms for Codeclew Rust, and 194 ms
for Codeclew Kotlin, versus 460/448/445 ms immediately before the compact-index
change. Observed peak RSS fell from approximately 231–239 MiB to 49–58 MiB.
These are local optimization measurements on the preceding source revision,
not release-wide latency guarantees or a qualification of forty repositories.

Kotlin evidence retains its reported partial semantic coverage; Rust analysis
remains syntax-backed. The common catalog and recovery-journal size bounds
remain unchanged. This release is a public macOS pilot, not a general
availability claim.
