# Codeclew v0.13.9 — start with one useful document

## A first overview without provider setup

`clew docs init` includes `examples/first-document.py`, offline help and runbooks.
The Python 3.11 standard-library starter uses the public CLI to register an
explicit source scope at committed HEAD, capture it and prepare one overview.
It resolves native handles/cursors and assembles complete source records into
one packet for the current agent. Maximal containing spans avoid repeatedly
sending overlapping nested source. Conflicting registrations require an explicit
update; existing starter edits and prior packets are preserved.

The `read` mode selects an exact saved snapshot and question without capture or
publication. Author the explanation, submit the native proposal and explicitly
publish locally with `--unassessed`, or use a configured independent review path.
The starter makes no provider calls and does not claim meaning approval.
See the [first-document guide](../operations/field-documentation.md#executable-first-overview-and-source-questions).

## Read the explanation before its optional details

Pinned-only publications show a neutral saved-source snapshot notice. The actual
`UNVERIFIED` freshness, revisions, reasons and meaning verdict remain accessible.
Missing sources or additional unknown reasons keep their warning treatment;
changed sources remain stale. This does not establish current checkout freshness.

Mobile navigation starts collapsed and closes after selection; the first screen
can show the explanation. Unexplained source entries remain accessible in a
separate disclosure. Recognized syntax declarations use readable names and file
labels in local navigation and the global catalogue. Exact symbols and IDs remain
searchable and available in disclosures. Source declarations are distinguished
from public entry points. Source evidence remains linked to the accepted version.
Section navigation records browser history, so Back returns to the prior section.
Older publication bytes are not rewritten.

## Recover with the actual error

Summary validation names the operation field, actual UTF-8 byte count and required
correction. Operation/gap conflicts identify their shared target. Exhausted finite
repair paths preserve the final validation feedback in `docs work status`.
Failure reports and published gaps explain the supported replacement route.
Driver output rejected before it becomes a native proposal requires corrected
output/configuration and new Work; no unvalidated prose is automatically admitted.

## Validation and limits

The v0.13.8 candidate was not published: its CI identified an obsolete diagnostic
assertion. This release validates the actual conflict target and corrective action.

The starter was exercised on a real committed Codeclew Python file through first
publication, a saved-source question packet and an update. Original owner-note and
publication bytes were preserved. The local publication remains `UNASSESSED` and
its unwritten sections remain explicit gaps. Deterministic generation fixtures
exercise correction, mandatory review and finite exhaustion without provider calls.

Desktop/mobile and keyboard checks assess the selected documentation workflows.
These checks do not establish full accessibility compliance, subjective delight,
remote billing/cancellation guarantees or automatic maintained-prose editing.
The public Codeclew narrative retains its reviewed v0.13.7 source snapshot; the
new reader does not silently reinterpret it against a newer checkout.
