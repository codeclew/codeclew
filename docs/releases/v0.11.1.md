# Codeclew v0.11.1 — faster saved reads and visible documentation phases

This fix release reduces repeated object-store admission during snapshot loading,
adds documentation phase diagnostics, and fixes disconnected generated overviews.

- Snapshot fact reads share one store admission and lifecycle barrier instead of
  repeating filesystem checks for every object. Every payload still passes size,
  digest and corruption validation; no reindexing or storage migration is needed.
- Documentation commands emit phase STARTED, HEARTBEAT, COMPLETED and FAILED
  events on stderr, including elapsed time and nested span identities. Heartbeats
  arrive about every five seconds. Stdout remains the JSON result. Set
  `CODECLEW_DOCS_PROGRESS=off` to disable these diagnostics.
- Diagnostics distinguish retained snapshot loading, context assembly, locks,
  compiler acquisition and publication. Heartbeats establish process liveness,
  not compiler progress. Source text and private identifiers are excluded from
  these events; existing external-tool output may contain other diagnostics.
- Proposal acceptance no longer invents overview nodes without edges. Short
  operations use their authored sequence, including branches and addressed
  returns. Explicit overviews remain validated. Long sequences still require a
  meaningful authored overview; old accepted artifacts are not rewritten.

A local saved-page comparison measured 24.988 seconds on v0.11.0 and 6.707 seconds
with this fix, with identical JSON output and no source acquisition. This is one
retained-cache measurement, excluding source-runtime build time, not a universal
speed guarantee. The reported 20-minute workplace stall was not reproduced.

A successful publication of one operation does not complete service sections.
Incorrect authored return destinations and ordering still need source review;
UNASSESSED meaning remains unassessed.

See [phase logging instructions](../operations/docs-snapshot-store.md#watching-a-documentation-command).
