# Codeclew 0.14.6 — independent Kotlin library source

A Kotlin/JVM service can explicitly associate a resolved Gradle dependency with
an independently captured Kotlin 2.4 library repository. Use `docs library
inspect`, `attach` and `docs recompose` to retain the library in the service's
immutable evidence closure. Work thread context, process graphs and HTML/MDX
exports can follow the reached library methods, their branches and returns, and
supported downstream calls. Unreached library effects do not become service
claims. The library remains an in-process source scope with its own repository,
revision and citations.

Compiler consumers retain the actual artifact SHA-256, size, variant and unique
classfile ownership. The source association remains `DECLARED_SOURCE_BINDING`:
matching coordinates, versions or JVM signatures never establish source-to-binary
equivalence or runtime dispatch. Mismatched versions/artifacts and ambiguous
associations refuse with repair guidance. Detaching and recomposing removes the
current continuation while existing immutable Work retains its earlier evidence.
Attachment and subsequent reads do not recapture the library.

SOURCE consumers can declare a revision-pinned dependency and follow a bounded,
unambiguous explicit Kotlin import as a candidate into retained compiler-backed
library bodies without building the consumer. The consumer call remains syntax,
the cross-repository edge remains declared/candidate, and the library facts keep
their original compiler authority. Overloads, receiver shadowing and unsupported
receiver expressions are not guessed. See the installed skill's
`references/library-sources.md` for the complete association and repair example.

Fresh Kotlin SOURCE captures also retain bounded local call-name navigation
hints. A retained helper can be read as a candidate without compiler-resolution
claims; old snapshots are not silently recaptured or augmented. Build tools are
not required for this SOURCE acquisition.

Portable, closed schemas and copyable CLI guidance now describe SOURCE
`read-part` and `read-batch` requests and responses, nested `SOURCE_ROWS`
selections, independent cursors, omissions and per-selection errors. Diagnostics
distinguish request fields from response fields without echoing invalid values.
Inspect every batch result independently; a successful envelope does not prove
complete source delivery. See `references/source-read-parts.md` in the skill.

Install or upgrade with `clew upgrade`, then refresh the installed Codeclew skill
through its supported installation command. Packages support macOS Apple
Silicon/Intel and Linux x86_64, including WSL2; Linux requires glibc 2.35+ and
Python 3.11+. The installer verifies published SHA-256 checksums.
