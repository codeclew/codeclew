# Codeclew v0.13.26 — documentation workflow recovery

This candidate builds on v0.13.25 and addresses two documentation workflow failures.

- Oversized Work DEPENDENCY records can be read through `docs work read-dependency-part`. Immutable UTF-8 pagination and complete validated receipts satisfy manual submission context without weakening the automatic packet delivery gate.
- Service readers keep source helpers in technical inventory without requiring a separate narrative for each non-boundary callable. Saved processes remain navigable; speculative internal process discovery is opt-in through `catalog/reader.json`.
- Check summaries separate public boundary counts from source callable candidates and provide a retained-contract recovery hint. The [agent recovery guide](../operations/documentation-agent-recovery.md) explains exact-reference selection and bounded recovery instead of repeating an unchanged failing submission.

Existing cross-service contracts and receiving service fragments are retained from v0.13.25. This release does not establish runtime routing, delivery, transaction commit, inherited generated-interface route discovery, or private-project acceptance. Private source and agent transcripts are excluded.

Publication requires successful CI on this candidate and the existing release qualification, architecture builds, installer smoke checks, and checksum verification. Local reader regression results are DOM tests, not browser or native runtime proof.
