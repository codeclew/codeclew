Codeclew 0.13.37 improves documentation language handling and retained-source DSL readers.

Selected native readers and HTTP contract readers can display owned interface text in English or Russian. Questions, authored paragraphs and original notes keep independent language declarations. An unavailable translation keeps the readable original, its provenance and an explicit gap; selecting a reader language does not translate source text or change its review state. Schema field names, constraints, enum values and defaults retain their recorded values. Existing source and section links remain stable across languages.

Java flow DSL documentation supports an unambiguous standalone inline builder chain from retained source. Conditional, nested, ambiguous and unsupported chains remain outside the admitted form. Readable interpretations, callback source links and original profiles remain available beside language gaps.

This is an incremental language update. Complete English/Russian coverage and independent visual acceptance across every documentation type remain unfinished. Full publication bodies, built-in help and runbooks still contain English interface text. The compiler-language parity work is not part of this candidate. These limitations must not be presented as complete bilingual documentation support.

The build-only release workflow qualifies the exact workflow commit and builds macOS arm64, macOS x86_64 and Linux x86_64 artifacts without creating a public tag or GitHub release. Public release publication remains a separate step after the required independent acceptance.

Retained evidence, declared contracts and editorial interpretations preserve their existing freshness, authority and runtime boundaries. Export does not establish application runtime behavior or publish a documentation website.
