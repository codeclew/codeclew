# Codeclew 0.15.13

Kotlin Gradle capture can now collect FIR facts during the project's selected
native compilation. Codeclew builds the observer against the project compiler
and runs it with the project's configured plugins, options and generated
inputs. The capture binds resolved calls to exact source spans, the selected
task and revision, and the resulting classfile hashes. Qualified replay remains
available for existing profiles.

## Verified configurations

- Kotlin 2.4.20, Gradle 9.6.1, and JVM 21 with kapt, Spring/all-open, and
  JPA/noarg. The fixture uses both explicit annotations and presets, checks
  generated Java calls, and verifies two generated zero-argument constructors
  alongside an unannotated control.
- Kotlin 2.4.10, Gradle 9.4.1, and JVM 25 with kapt, Spring/all-open
  annotations and presets, and a separate Java source generator attached to
  `compileJava`.
- Kotlin 2.4.20, Gradle 9.6.1, and JVM 21 with explicit all-open annotations
  and project compiler flags. The fixture resolves two overloads on the same
  source line and verifies the emitted classfiles.
- Kotlin 2.2.21, Gradle 8.14.1, and JVM 21 with Spring and kapt.

These results cover the listed configurations. Capture coverage can remain
partial when some constructs or project inputs cannot be verified.

## Offline diagnostics

Failed Kotlin Gradle captures now retain a shareable compiler plugin diagnostic.
The first unavailable or failed native kapt check and the actual ABI rejection
are recorded separately. Run `clew support collect --root ROOT --snapshot SNAPSHOT
--output NEW_DIRECTORY` to inspect the saved facts offline. The report identifies
the original failure runtime separately from the collector. Earlier failures
report the diagnostic as unavailable.

Codeclew remains a public pilot for macOS and Linux. Upgrade with
`clew upgrade` or use the [installation guide](https://codeclew.github.io/codeclew/).
