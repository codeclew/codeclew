# Codeclew 0.15.3 — large evidence packages and retained export

Portable evidence now admits up to 2,097,152 aggregate records, matching the
existing 4,096-part native layout. The 128 MiB total and 2 MiB per-part byte limits
remain enforced. Limit failures identify the bound, declared count and limit;
validation progress distinguishes package limits from payload verification.
No records are truncated to fit.

Export a successful saved Check without compiling the service again:

```sh
clew docs evidence export --root DOCS_ROOT --service SERVICE_ID --snapshot SAVED_SNAPSHOT --output NEW_PACKAGE_DIRECTORY
clew docs evidence inspect --input NEW_PACKAGE_DIRECTORY
```

The command reads only the selected service's original declaration and retained
capture. Its checkout and unrelated service captures may be unavailable. It keeps
source fragments, observations, entrypoints, contracts and original bindings.
Missing or corrupt selected evidence is refused instead of triggering capture.

Historical packages explicitly bind the original snapshot and capture identities.
Inspection does not grant trust: import still requires the configured exact
service/revision and trusted manifest digest. Imported historical evidence stays
`RETAINED_SOURCE_NOT_REVERIFIED` and `NON_CACHEABLE`; it does not become proof of
current compiler/build state. Existing fresh schema 1.0 packages remain supported.
Maven external-build authority and package integrity protections remain in place.

Owned scale fixtures cover the reported Java record volumes and complete typed
record conservation. This does not establish that a private project was replayed.
Public pilot platforms remain macOS Apple Silicon, macOS Intel and Linux x86_64,
including WSL2.
