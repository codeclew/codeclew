# Codeclew v0.10.0 — independent checks, compact storage and internal processes

This release addresses field failures that delayed documentation behind repeated
capture and hid internal behavior behind an API-only inventory. It adds
independent retained service checks, compact local object storage and a process
catalogue that remains useful before an explanation has been authored.

## Saved analysis and service checks

- A selected service check preserves compatible saved sibling results. The reader
  distinguishes retained evidence from source inputs reverified by this command.
  A selected failure cannot silently restore the old selected result.
- Concurrent checks against one documentation root serialize their update,
  including when their runtime homes differ.
- Qualified committed, no-processor Java analyses retain successful analyzer
  output by complete compiler inputs. Unrelated repository revisions and Rust
  documentation projection changes no longer require a new Java subprocess.
  Current model, provenance and query structures are rebuilt from saved facts;
  the original compiler execution receipt remains distinct.
- Native Java 17 reuse is qualified on macOS arm64, alongside the existing narrow
  Java 21 execution-image policy. Source, ordered classpath, JDK image, compiler
  options and executor policy participate in the key. Annotation processors,
  transformed inputs and other unqualified executions remain outside this cache.
- Build-added Java source membership is frozen after the admitted Maven build.
  Writable capture retains exact transformed bytes; it does not invent original
  commit links for generated source. Read-only capture refuses those extra files.

Maven model extraction and required reactor builds can still execute on an
explicit check. Zero Java analyzer starts does not mean zero Maven work. Saved
context, Work and rendering start neither unless refresh is explicitly requested.
The updated agent guide makes this distinction explicit and describes a
source-first workflow for an initial document without Maven.

## Storage and resource use

- Documentation roots use SQLite exclusively for immutable payloads, avoiding a
  file and directory for every fact. This is a fresh-state release: create a new
  documentation root and reindex services. The durable root manifest is version 2.0.
  Old formats are rejected explicitly;
  there is no migration, loose-object fallback or automatic data deletion.
- Check and Work records require current snapshot references. Bindings and
  narratives use schema 1.3 only. Semantic providers are configured through
  `modules.semantic`; the former `source.semantic` field is rejected. Native
  services declare `compilations`, including a one-element list for one scope.
  Saved definitions require process/view metadata; plain scenarios are rejected.
- A Git clone of a current-format documentation repository can explicitly
  initialize its missing local state with `docs init`, then bind and reindex its
  sources. A partial private directory is not treated as a fresh clone.
- A missing or corrupt selected database fails explicitly; it is never silently replaced
  by an empty cache. Current-format pins and snapshots share immutable objects.
- Capture and check manifests share canonical per-fact payloads. Publications no
  longer create unused CAS copies of their already portable inline evidence.
- Fact membership updates use linear winner selection instead of repeated scans.
  Equal source text and line indices share memory across compilation scopes;
  distinct transformed text and scope provenance remain separate.

SQLite was selected for its local transaction and multi-process ownership model,
not as the universally fastest engine. Comparative prototypes also evaluated
RocksDB and indexed packs. History is not
automatically garbage-collected. Older binaries must not write a current-format
root. See the [storage guide](https://github.com/codeclew/codeclew/blob/v0.10.0/docs/operations/docs-snapshot-store.md).

## Internal processes and model context

- `docs process candidates` discovers structural candidates from retained evidence,
  with separate internal and trigger lanes and explicit callable roots.
- Service pages show internal processes, pending explanations and evidence gaps
  even when there are no public HTTP handlers. Candidates are not automatically
  accepted business processes or an exhaustive inventory.
- The `process-v1` Work profile shares overlapping source text and defers large
  callable records behind expansion handles. Navigation summaries and text aliases
  do not authorize citations to unread provider facts.
- Scope-qualified roots distinguish matching symbols in different compilations.
  Cross-scope bodies are not traversed without a verified mapping; a test-module
  method cannot become production behavior merely because its JVM name matches.
- Syntax-derived candidates retain lexical ordering and unresolved calls. Compiler
  facts, declared integrations and agent explanations keep separate authority.

Computational facts remain reusable outside documentation. Dedicated plugin SDKs,
DMN semantics and additional independent artifact generators are not delivered by
this release. The existing narrative, contract, sequence and dataflow consumers
remain the supported artifact paths.

## Measured reuse on a public fixture

A three-scope Maven fixture on macOS arm64 with the qualified no-processor JDK 17
profile produced these analyzer counts. Every accepted arm used the same runtime;
receipt identity and saved payload hashes were checked separately.

| Changed input | Reused scopes | New analyzer starts |
|---|---:|---:|
| Unrelated Git commit | 3 | 0 |
| Source in one scope | 2 | 1 |
| Shared dependency JAR | 0 | 3 |

These checks took about 11–14 seconds after runtime preparation; Maven remained
in the execution path, without a phase-by-phase timing breakdown. This demonstrates
selective compiler reuse, not a measured speedup
for large workplace repositories. Seven retained raw checkpoints occupied
11,386 unique output bytes plus 4,473 envelope bytes in this small fixture.

## Qualification boundaries

The public fixtures cover generated sources, JDK 17/21 reuse, selected-service
retention, obsolete-format rejection and offline documentation consumers. They do not
reproduce inaccessible workplace sources, annotation processors or deployment
behavior. The existing admission limit remains 128 compilation scopes; it is not
a guarantee for arbitrary code volume or memory demand.

Use the [first-document and selective-refresh workflow](https://github.com/codeclew/codeclew/blob/v0.10.0/docs/operations/field-documentation.md)
to obtain a bounded source explanation, preserve its publication, and request
compiler evidence explicitly when it adds value.
