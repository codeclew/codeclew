# Codeclew v0.12.1 — experimental endpoint reader packet (public pilot)

This patch adds an opt-in, experimental authoring path for one captured Java
HTTP endpoint. It does not switch the general documentation pipeline to a new
author path or change native publication behavior.

## Saved-evidence packet

- `endpoint-context-v3` selects bounded direct DTO fields, retained method
  sources and call context from immutable Work. Run
  `clew docs work packet --root ROOT --work WORK_ID` to emit a compact packet;
  `--audit-output FILE` writes the full selected rows, Work handles and digests
  separately for verification. The audit is not part of the author packet, and
  generating either projection does not record ordinary Work read receipts.
- Compiler field and constant declarations retain their captured
  `jvmDescriptor`; older source-syntax `typeDescriptor` values are preserved
  when available. A source-reference candidate such as `this::send` remains a
  lexical candidate, not an immediate call at that location. The call map is
  not execution order, and runtime or serialization effects remain unknown.
- Packet creation reuses the saved snapshot and performs no source acquisition
  or reindexing. If an older export lacks needed relation or source facts, a
  new capture is required to obtain them; the packet cannot reconstruct facts
  that were never retained.

## Offline answer draft

`clew docs work explain --root ROOT --work WORK_ID --input ANSWER.json
--output-dir DIR` accepts one external structured answer conforming to
`codeclew-operation-answer/1.0`. It checks the answer's packet digest and
evidence labels against the saved Work packet, then writes HTML, Markdown, a
derived operation tree and binary decision tables. Reusing the output directory
updates the current draft files, each by an individual atomic replacement; the
set is not transactional. If a run stops between replacements, rerun with the
same saved Work and answer to finish the draft, without index capture. The
command does not publish documentation or create a release/version entry. The
generated result is always `DRAFT` and `UNREVIEWED`. Validation checks structure
and evidence-label binding, not the semantic correctness or quality of the
explanation.

## Limits and qualification

This remains a public pilot. The endpoint packet does not establish dynamic
dispatch behavior, complete inherited fields, generic payload specialization,
wire serialization or runtime effects. The external-answer renderer does not
produce a complete DMN model. No additional model-quality or Luna qualification
is claimed by this patch.

Older Work prepared with endpoint-context-v1 or endpoint-context-v2 is rejected
by the v3 selector and must be prepared again. Re-preparation can reuse an
existing saved snapshot, but facts absent from that snapshot require a fresh
capture. These features do not qualify the overall documentation workflow or
claim that generated prose is ready for publication.
