# Codeclew 0.15.8 — focused documentation authoring

Prepared documentation runs now use an explicit current-page handoff into a
fresh inference context. The input retains complete selected source views,
the current draft, author notes, pending decisions and a full scope index.
Earlier conversations and completed unrelated page bodies remain saved without
being replayed. Thread identities and historical usage stay explicit; a fresh
context does not reset the aggregate budget or hide unavailable counters.

Each run completes or reports a failure for one selected page. The caller
prepares the next handoff and explicitly runs final verification and promotion.
Interrupted or failed attempts cannot silently dispatch another author.
Independent rejection reopens the affected page decisions while preserving the
parent, source bindings, earlier drafts and reported costs.

The author tools provide addressed source/reader comparisons, canonical source
review references, stable fragment and Data links, scoped route repair and
compact local diagnostics. Page and final checks share presentation, provenance,
discovery, sequence and renderer rules. Hidden or empty field tables and literal
text lost to unintended HTML are rejected rather than counted as reader content.

Concurrent retained-source navigation and source-part reads now wait for the
short receipt commit and merge the current ledger instead of failing with a
writer conflict. Ordinary mutation locks retain their conflict behavior. Failed
source-membership reads preserve bounded native and transport causes for diagnosis.

Use the packaged skill's `references/documentation-runner.md` for the
`prepare`, `handoff`, `run`, `verify` and `promote` commands. Mechanical checks and
recorded author judgments do not establish semantic completeness or runtime
behavior; independent source and reader acceptance remains necessary.
