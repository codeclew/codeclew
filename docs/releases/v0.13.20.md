# Codeclew v0.13.20 — core Kotlin analysis and saved diagnostics

Save a diagnostic bundle from an existing documentation Check without another
source capture:

```sh
clew support collect --root /absolute/docs-root --output /absolute/new-bundle
```

The report retains the exact snapshot, manifest size, separate Check outcome,
service selection/retention and entrypoint counts, typed original failures,
known runtime metadata and safe worker/Maven process details. Historical Checks
remain inspectable after current declarations change. Missing or corrupt metadata
and active SQLite WAL/journals explicitly produce `PARTIAL`. Collection reads
only manifest metadata; it neither hydrates source/fact objects nor modifies the
documentation store. Snapshot/content digests and hashed identities can correlate
a repository and should be reviewed before sharing.

For the next invocation, including errors during runtime preparation:

```sh
clew --diagnostics /absolute/new-run-bundle --include-private-logs \
  docs check --root /absolute/docs-root --service orders
```

The command runs once and retains its stdout, stderr and exit status, including
nonzero unresolved Checks. Diagnostic notifications go to stderr. Private log
capture is opt-in: terminal tails, live worker stderr and the same run's Maven
failure output are bounded and stored with private permissions. Original saved
failure text is separated from the default allowlisted report. Old external log
paths are never imported, and no upload occurs. Interruption terminates the child
group even after its output pipes close. In this opt-in mode stdout/stderr are
pipes, so terminal detection and progress presentation may differ.

Retained-service errors now preserve the recorded capture reason and exact
snapshot instead of suggesting another capture for a service that already failed.
See the [diagnostic guide](../operations/support-diagnostics.md) for limits and
the distinction between diagnostic completeness and successful source capture.

Core now contains the sole Kotlin 2.4.10 analyzer for supported Kotlin 1.9–2.4
projects, including Kotlin 2.3.0. Separate Kotlin 2.3 assets and pack commands
are retired. Original project compiler/language/API identity remains retained;
compiler plugins, `-X` options and Kotlin 1.9 language-upgrade boundaries stay
explicit. Native compiler equivalence, general mutation qualification and
Kotlin 2.5+ support are not implied. Historical saved engine identities remain
readable and are never relabeled or used to launch a retired analyzer.
The existing Kotlin 2.3 Maven read-only profile now checks readiness against
core 2.4.10 and reports conditional analysis authority.

If an older installed release uses the optional Kotlin 2.3 profile, switch that
old release to its existing core with `clew pack remove kotlin23`, then run
`clew upgrade`. Its old updater cannot automatically choose core while still
in the retired profile. Alternatively use the current public installer with
`CODECLEW_PACKS` cleared. See the [installation and migration guide](../../README.md#install-on-macos-linux-or-windows-through-wsl2).

Existing documentation and language capabilities remain included. C# remains
the read-only Roslyn preview requiring .NET SDK 10+ and restored project inputs.
This public pilot supports macOS Apple Silicon/Intel and Linux x86_64, including
Windows through WSL2. Linux requires glibc 2.35+ and Python 3.11+. The installer
verifies published checksums and does not compile Codeclew on the user's machine.

```sh
curl -fsSL https://codeclew.github.io/codeclew/install.sh | CODECLEW_PACKS= CODECLEW_VERSION=v0.13.20 sh
```
