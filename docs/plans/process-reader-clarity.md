# Process reader clarity

## Problem and first slice

Develop did not contain the source-bound `process.thread` projection used by the
retained review bundle. Process pages also mixed declared goals, explanations,
source outlines and publication diagnostics. Readers could confuse reading order
with execution order or mistake exact source binding for relationship authority.

This slice restores the bounded Kotlin/Java thread contract, native projection
and Markdown source closure. The reader opens with summary, trigger and
participants, shows explicitly selected connection declarations independently
from resolution checks, and retains source citations and visible thread limits.
Publication diagnostics and additional outlines remain available on expansion.
Missing step kinds preserve old serialization; explicit kinds are declarations.
Kotlin root lookup uses retained observations without changing their authority.

## Acceptance boundaries

Exact methods, source ownership, digests, roots, references, citation bounds and
escaping are machine checks. Business labels, intent and useful explanations
remain review judgments. Declared topology does not prove deployed routing;
save/send calls do not prove commit/delivery. Generic DTO updates do not define
a strict FSM. Budget cuts and semantic boundaries must remain distinct in a
future extractor. These steps are an implementation plan, not an approval layer.
