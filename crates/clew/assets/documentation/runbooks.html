BUNDLED CODECLEW RUNBOOKS

Operate your documentation repository

These procedures are available immediately after clew docs init. They concern Codeclew itself. Add service-specific incident procedures from source, operational evidence and owner notes; installing the CLI cannot supply your production knowledge.

Move to a fresh laptop

  1. Install Codeclew and its agent skill. Clone the documentation repository, including committed evidence and history.
  2. Clone the service repositories separately. Rebind every service with clew docs bind --root . --service SERVICE_ID --repo /path/to/checkout.
  3. Run clew docs check --root .. Inspect unavailable source, stale explanations and unresolved links before asking the agent to update them.
  4. Open docs/index.html after a publication, or docs/help.html before the first publication.

A process inspection looks frozen

docs process inspect is a read-only source inspection. A first compiler run can need build metadata and dependencies; terminal JSON appears when the inspection completes. Check that the command runs in the documentation root and that its declared participants are locally bound. Source-syntax inspection should not load unrelated publication history.

If a run remains blocked, interrupt it and run clew doctor repository --repo /path/to/service --committed. Retain the reported diagnostic code and ask the agent to inspect its local diagnostic output. Do not delete private runtime state to force a retry.

A write reports a digest conflict

  1. Read the relevant list/show response again.
  2. Compare the current record with your intended update.
  3. Retry the reconciled update using that response's full inputDigest. For note associations, also read the original note digest.
  4. Check the saved record. A retry should preserve another author's work.

An explanation is stale or incomplete

Run docs check, inspect the affected service/process and ask the agent to refresh the affected roots through the documentation work/proposal commands. Keep unsupported branches as explicit gaps. Source freshness and meaning review are separate: CURRENT does not mean VERIFIED.

K2 evidence is unavailable

Check the repository doctor result, installed runtime variant, Java/Kotlin versions and configured profile/compilation. Inspect the service's Analysis evidence panel for the provider status and reason. Source-syntax documentation stays readable if optional enrichment fails; do not label it compiler-verified. Restore the reported prerequisite and check that service again.

Add a service incident runbook

Give the agent a service, symptom, environment and date, then ask for: entry and exit points; affected entities and scenarios; diagnostic commands with expected results; recovery steps and authorization constraints; post-recovery verification; escalation owner and unresolved questions. Store your original operational observations as associated notes. Ask it to distinguish source-supported behavior from deployment observations and proposed procedures.
