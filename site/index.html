Install and check your version

Use Git and Python 3.11+ on macOS, Linux or WSL2. The installer selects the latest published release. Each task links the recorded version, scope and results of its example.

macOS · Linux · WSL2Published releases ↗
curl -fsSL https://codeclew.github.io/codeclew/install.sh | sh
clew --version
clew capabilities --human
clew skill install --agent codex

Use the printed launcher location if clew is not on PATH. Update with clew upgrade. Your chosen agent writes explanations using its own model and data settings.

Platform and compiler requirements

Prebuilt packages cover macOS arm64/x64 and Linux x64 with glibc 2.35+. On Windows, use WSL2 and keep the repository in its Linux filesystem. Committed Python, Java and Kotlin source documentation needs no application build. Kotlin compiler analysis requires JDK 21 and a supported project profile. Other compiler paths use their project toolchains.

C# read-only preview: project requirements and limits

Roslyn-backed C# reading and analysis is included since release 0.13.11. Packaging and real C# checks passed on all three supported platforms; the public case also ran through the officially installed package. F#, Visual Basic and other .NET languages are outside this profile.

Use a .NET 10+ SDK and restore the selected project yourself before analysis. Select language csharp, profile csharp-dotnet-msbuild-read-only, and an exact repository-relative csproj:<path>[@<tfm>] or sln:<path> for .sln or .slnx. Check installed capabilities and repository discovery before selecting a compilation.

Supported source facts include selected declarations, calls and ASP.NET Core MVC attribute routes. Unrestored inputs, generated sources, custom controller discovery, conventional routes, minimal APIs and API-version URL formats remain explicit limits. From selected source to an answer

  1. Select a snapshot and scope. Name the repository, committed revision or saved edits, language and compilation.
  2. Keep the evidence. Clew retains supported declarations and source with their identities, coverage and explicit gaps.
  3. Ask your agent. Read the returned source, write the useful explanation, and keep citations tied to that evidence.
  4. Choose the next check. Open a source link, verify freshness, request missing context, or run the project checks the answer calls for.

Analysis runs locally. A model-authored explanation is an interpretation of the selected source; it does not establish deployed behavior. How to assess a result →

Keep the answer tied to its evidence

Capture acquires the selected source for an explicit scope and saves a Check. Questions can read that saved evidence without a fresh capture. An agent supplies the explanation; where supported, an independent meaning review records its decision against the packet it actually received. Neither step proves live runtime behavior.

Included in release 0.13.17: an exact method-question lookup can find a saved approval and compare its dependencies with an explicitly selected Check. A relevant source change, a newly matching result or unsupported context prevents reuse. One applicable answer is returned directly; several require an explicit choice. The original approval and citations stay frozen, while current source-link changes are reported separately. Finding an answer does not republish the reader.

When a new capture is needed, unchanged syntax extraction can be reused within its exact service, path, content and producer boundary; current source occurrences are rebuilt. Compatible model drivers can separately send a compact evidence presentation while the complete delivery remains in the archive. These are distinct savings: fewer repeated source operations, fewer unnecessary model calls, and less repeated text in a model request.

Read the included capabilities and limits or the capture, question, review and reuse workflow.

Choose what you share

Clew needs no hosted model or API key for local analysis. When you use an agent, that agent's provider and sharing settings apply. Keep private source and operational observations in the appropriate repository. Inspect support material before sharing it.
