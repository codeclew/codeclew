Start with a concrete engineering question

For example: “Find methods with this scheduling annotation and show their exact source.” Add a supported case, an unrelated namesake and a missing-input case. Describe what the result means and where it should abstain.

This is product source development. Use native repository tools and ./clew in your checkout; installed clew is the public-release launcher. Build providers and adapters are internal interfaces, not a public drop-in plugin loader.

Contribute within the C# preview scope

Follow the exact project selector and compiler inputs, Roslyn worker, and portable facts before changing framework interpretation. The released read-only profile targets C# .csproj, .sln and .slnx inputs; it does not promise F#, Visual Basic or general .NET support.

Use a .NET 10+ SDK and restore the chosen project yourself. Verify worker behavior separately from Rust tests. Keep generated or unrestored inputs, custom controller discovery, conventional routing, minimal APIs and API-version URL formats explicit. MVC attribute-route source facts do not establish deployed endpoints.

The profile is read-only and rejects candidate generation. A new fact or route rule needs a source fixture and a missing-input or unsupported case; it does not enable managed writes. Published release checks and installed C# results.

Verify the changed behavior

Read the checkout's contributor instructions and build requirements. Choose focused checks for the code or worker you changed. Documentation and site contributions need syntax, local links, search destinations and English content checks.

python3 -I -S scripts/build_site_navigation.py --check
python3 -I -S scripts/test_site.py
python3 -I -S scripts/check_english_content.py

Keep Rust-only verification separate from compiler-worker correctness. The repository's full CI gate applies when preparing a merge-ready change.

Make the contribution reviewable

Include the before/after result, selected fixture, checks run and remaining limits. Version changed contracts and update their producers and consumers together. A new read capability does not automatically authorize managed writes.

Keep the canonical skill and its agent copies identical when changing the package. Keep private paths and data out of the repository, and run the repository privacy check before publication.
