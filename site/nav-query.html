Task 01 / Find

Find the code

You know the name of a function. Find its declaration, inspect the selected source, and decide whether it answers your engineering question.

Try the public source case →
Run with installed Clew 0.13.11. The public case selected one exact declaration and returned its saved source. A separate no-match query abstained. Read the recorded result.

Start with a question the source can answer

Public case: where is fair_fact_selection, and how does it choose the facts returned to a caller? Use a committed Clew checkout. Git and an installed launcher are enough to begin repository discovery.

If you do not know an exact name, ask your agent to discover the relevant declarations first. Supply a name only when your task or returned records justify it.

Discover the repository, then query one exact name

git clone --branch v0.13.11 https://github.com/codeclew/codeclew.git codeclew-example
git -C codeclew-example switch -c read-example
checkout="$PWD/codeclew-example"
clew --version
clew doctor repository --repo "$checkout" --committed --human

Read the discovered profiles and compilations. The recipe below selects the Rust library target shown in the source repository's navigation example. Use a branch or tag that exists in your checkout; pin and record its commit before interpreting the result.

clew nav query --repo "$checkout" --target-ref read-example \
  --language rust --profile rust-syntax \
  --compilation "cargo:crates/clew/Cargo.toml#clew#lib#clew" \
  --term fair_fact_selection \
  --decision-identifier fair_fact_selection --source

Inspect the returned response: its decision authority, selected declaration, source range, source text and coverage. Candidate cards alone do not identify the function you meant. A supported selection needs one exact matching declaration and the recorded decision checks.

The recorded decision is SUPPORTED / UNIQUE_EXACT_IDENTIFIER_FULL_COVERAGE: one exact match among three returned candidate cards. It selects fair_fact_selection in crates/clew/src/query_v2.rs:364–391 at release revision d91dbec. The complete declaration window is EXACT_SNAPSHOT_TEXT; the surrounding file is not a complete returned source file.

Ask for the answer with its source

Read the source returned for fair_fact_selection. Explain how it chooses facts and which limits it preserves. Cite the returned file and source range for each material claim. Separate the algorithm in this snapshot from anything you cannot establish.

The source-backed answer: each term's matches are first grouped into families by semantic_fact_key and interleaved across those families. That helper was read separately from the same retained context. Read the helper at lines 393–424 ↗.

The main function walks the term lists in rounds, taking the next unseen fact from each list. It skips duplicates and stops when it reaches the requested limit or a round adds nothing. A BTreeSet deduplicates facts and determines the returned order; the selection rounds are not the final output order. Read the selected declaration ↗.

The recorded source windows retain both functions and their digests. The body of semantic_fact_key was not read in this case, so its normalization rules remain outside this answer. Rust syntax locates the declarations and retains exact text; it does not resolve a compiler call graph or prove deployment behavior. Returned completeness remains CONDITIONAL_TASK / QUERY_COMPLETE / UNSURE.

Use a no-match result to choose the next step

clew nav query --repo "$checkout" --target-ref read-example \
  --language rust --profile rust-syntax \
  --compilation "cargo:crates/clew/Cargo.toml#clew#lib#clew" \
  --term no_such_clew_example_function \
  --decision-identifier no_such_clew_example_function --source

This deliberately unrelated name returned zero candidates and ABSTAIN / UNMATCHED_EXPLICIT_TERMS. Its next action is STOP_UNRESOLVED: do not repeat the request or choose an analogue. Continue only when your task or exact retained source supplies a different identifier or a known file. Otherwise keep the question unresolved.

A missing build input calls for correcting discovery or the selected profile. An ambiguous name calls for inspecting the candidate identities. An unsupported language or compilation calls for selecting a supported scope.

Use the result

Repeat this with one question from your repository. If the explanation needs to survive the conversation, create a first document. If you are deciding what a saved change affects, review saved edits.
