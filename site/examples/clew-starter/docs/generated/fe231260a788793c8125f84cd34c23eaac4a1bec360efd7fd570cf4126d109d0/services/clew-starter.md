# Prepare a first document

Static source interpretation. Declared interactions do not establish runtime routing.

## Overview

first-document.py prepares an authoring task for a first overview or a question about saved source. It accepts an initialized documentation root, service and audience, plus a Clew launcher (default: clew). Capture needs a local Git checkout, repository URL, Python/Java/Kotlin language, declared dialect and repeatable committed source roots; read needs an exact saved snapshot and question.

The source describes capture resolving committed HEAD, comparing the service registration before adding a missing service, then invoking bind and check and requiring a returned snapshot. Read uses the supplied snapshot. Both prepare overview Work, record paginated context and a SOURCE inventory, select source spans while preserving separate authority groups, and read complete retained parts. The CLI wrapper expects JSON and accepted exit codes.

A fresh authoring/first-document-* directory receives context, inventory, source-part JSON, a Work request, packet.md, an intentionally incomplete proposal.json, result.json and CLI progress; capture also writes service.json and check.json. The successful path ends at READY_FOR_AUTHOR with NOT_PUBLISHED. Read the packet and complete parts, then replace the proposal title, summary and empty evidence with source-supported content. The starter prints a later submit command.

This overview is grounded in retained Python syntax/declarations and lexical order. Import declarations are present, but imported implementations, resolved call targets, runtime dispatch and Clew CLI implementation semantics are not established; the declared dialect is not compiler-validated.
