Start locally with one service.

Document committed Python, Java or Kotlin source even when the application cannot build. Register its source scope, capture evidence, and ask your agent to explain responsibilities, entities, inputs, outputs and failure cases. Optional compiler facts enrich the same documentation.

Keep services, scenarios and entity dataflows in a separate documentation repository. The offline reader includes source references, interface cards, declared OpenAPI contracts, protected notes, publication history and visible gaps. Source freshness and meaning review are separate: local publication can remain UNASSESSED.

Service-documentation visuals · v0.13.7

Follow the flow

Source-linked nodes and arrows explain supported action order and branch conditions. A dependency map shows structural relationships and does not imply execution order.

Understand a decision

Retain the evidence

Visuals share their containing explanation's saved version, freshness and meaning review. A source change can flag them for another look without automatically rerunning a model.

This is an authoring workflow over saved evidence, not automatic discovery of every business process. Selected flows do not establish complete service coverage or runtime behavior. Decision tables document source interpretation; they are not executable DMN. The experimental method draft below is a separate local-only artifact.

Included from the first command

A fresh repository already has help.

Run clew docs init --root ./architecture --title "Service documentation". Open architecture/docs/help.html for Codeclew setup, agent prompts, notes, scenarios and dataflows, or architecture/docs/runbooks.html for Codeclew operational procedures. Both guides work offline and exist before you register the first service.

New publications share navigation, the Codeclew favicon and the blue and cream reader theme. Service-specific runbooks come from your source and owner knowledge. Older publication URLs retain their original immutable pages.

The top-level clew --help now lists skill; use clew skill install --agent codex to install the bundled agent instructions. To move existing documentation, preserve its current-format saved state and first inspect the retained snapshot. Bind source checkouts with clew docs bind when a source check is needed; use clew docs check --service SERVICE_ID for the selected service. Reading or publishing saved evidence does not require a new capture.

RETURNED_INPUT_DIGEST in command examples means the complete inputDigest returned by the preceding list or show command, including sha256:. It protects a catalogue update against concurrent changes.

See what compiler analysis added

In a service page, open Coverage and evidence → Analysis evidence. Inspect the provider status, mapped declaration count and example semantic facts. For Kotlin 2.3 projects, install the optional kotlin23 pack and configure an admitted semantic profile. K2 can add resolved identities, types, nullability and JVM signatures; syntax-only pages explicitly show that the provider was not requested. Compiler facts do not establish deployed connections or reviewed business meaning.

Native source pages · v0.13.7

Follow selected calls between documented processes.

clew docs pages render exports linked process overview, endpoint, worker, field/state and diagnostic pages from an exact saved Java snapshot. Select callable roots; the projector derives supported conditions, transformations, call boundaries and local uncertainty from retained source without a pre-authored answer.

Set "expandSourceCalls": true on each participating selection. Exact retained compiler call occurrences can link parent pages to a uniquely selected child endpoint in the same service and compilation scope. Worker calls can open retained helper bodies in source-calls.html and MDX; repeated calls retain their distinct occurrences. These source links do not establish receiver identity, runtime dispatch, queue scheduling or delivery.

Expansion is bounded to depth two, 64 additional bodies and 1 MiB of additional source text. Cycles, ambiguity, scope mismatches, missing bodies and dependency boundaries remain visible frontiers. A separate examinedSourceDigest and reverse membership identify review candidates within the examined source. A shared child helper change can identify both parents; unrelated global revisions and coordinate-only relocation with unchanged retained text leave that local digest unchanged. Whole-bundle and file hashes keep their existing meaning.

Search native pages by readable callable name, exact signature or supplied question. Open the retained helper and its examining processes; expand Exact identity for the complete compiler signature and ID. One typed projection supplies inert MDX 3 and standalone HTML, relative navigation and source appendices. With expansion disabled, ordinary output remains unchanged. Older snapshots remain usable offline; selected source does not establish complete process coverage or runtime impact.

Grounded questions · v0.13.7

Keep the answer close to the code.

A selected Java method and persisted question define one immutable Work. The configured author receives admitted source data and conditions; an independent configured reviewer assesses the complete saved answer against that packet. An approved reader keeps the question, citations, review limitations and source version together.

Use docs work review-draft to review, docs work explain --review-run to export, and docs work publish-answer with an exact publication baseline to admit an approved answer explicitly. docs work answer-context compares that answer with a new captured Check and reports CURRENT, STALE or UNKNOWN separately from the original meaning verdict.

Model execution requires an explicit isolated driver and finite configuration; no provider is selected automatically. Actual author/reviewer execution was qualified on macOS with owned Java cases. A model verdict does not prove runtime behavior, an observed incident cause or agreement with later code. Author calls in the five-case qualification exceeded the 60-second target.

Maintained documentation · v0.13.7

Keep the text. Select its source context.

Read a large retained operation in bounded parts, then edit its title or one exact explanation paragraph through the manual Work and proposal path. explanationText changes the paragraph text while preserving its effective source context. The separate explanationContext instruction selects current saved context without changing the text, paragraph identity or declared text author.

Context selection records a separate declared context editor, previous snapshot and context digest. It requires complete retained-operation and current source reads, matching baseline digests, compatible logical source/dependency references and exact current event anchors. Regenerate stale source-derived fields first. Changed scopes, ID remapping, unread evidence and conflicting baselines are rejected.

Publish the prepared manual proposal with --unassessed. Text meaning and selected context remain UNASSESSED; CURRENT describes local source freshness. A later source change can mark the selected context STALE without silently rebinding it. Later text corrections retain the selection, and older publications preserve their original bytes.

Native source pages can include an exact frozen publication's authored paragraph beside current generated content, with its own original or explicitly selected source links. Captured operational notes remain a separate selection from the saved Check, preserving their wording, attribution and version.

Keep what your team knows

Add a note to the thing it explains.

Ask your agent to attach your original Markdown note to a service, one of its standard sections, a scenario, an entity definition or a dataflow. One note can address several objects. Preserve the original wording and keep the evidence-based answer separate.

For example: “Attach this question to entity:reservation: Does TTL still apply after confirmation? Preserve my wording, investigate the registered source, and document the answer with evidence and remaining uncertainties.”

Notes use Markdown and typed associations; the reader has no comment composer or discussion threads in v0.13.7. For a specific method or paragraph, use a section target and identify the exact subject in the note. That text is a focus hint, not a validated source anchor.

Keep its limits visible

The example does not establish a runtime caller, runtime execution order, later dispatch, external effects, database persistence or deployed behavior. It is one source-local scenario, not complete workflow qualification.

Native status remains DRAFT / UNREVIEWED and publication is NOT_PUBLISHED.

The configured author path in this recipe requires macOS Seatbelt. Linux supports source capture and external structured-answer rendering; this example does not qualify author execution on Linux. Hosting the checked-in reader here makes the sample viewable, but it does not change its native draft, review or publication status.

Sample provenance records one configured author call of 164.078 seconds and a saved-result replay that made no new author dispatch.
