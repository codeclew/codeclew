Create a first document

Start with one committed script. Keep a useful overview next to the source your colleague can open.

Created with installed Clew 0.13.11. The first overview, saved-source question and preserved update were executed. Read the observed record.

Select one small committed source scope

Public case: document scripts/build_cli_documentation.py from a Clew checkout. The useful question is: “What does --check verify, and when does this script invoke Graphviz?” Use Git, Python 3.11+, the installed launcher and a separate documentation directory.

Capture selects committed source at the checkout's HEAD. Save the source revision with the result. Unsaved editor buffers and later saved edits are not part of that snapshot.

1. Prepare the source and authoring files

git clone --branch v0.13.11 https://github.com/codeclew/codeclew.git codeclew-example
git -C codeclew-example switch -c read-example
checkout="$PWD/codeclew-example"
clew docs init --root ./architecture --title "CLI documentation generator"
python3 -I -S architecture/examples/first-document.py capture \
  --root ./architecture --repo "$checkout" --service cli-documentation \
  --title "CLI documentation generator" \
  --repository https://github.com/codeclew/codeclew \
  --language python --dialect 3.11 \
  --source-root scripts/build_cli_documentation.py

Use the starter created inside the new documentation root by your installed release. It makes no model calls. Its response names the Work, snapshot and an authoring directory containing packet.md and proposal.json. Use those actual returned paths; the proposal template still needs an authored explanation.

2. Ask your current agent for one useful overview

Read packet.md completely and write the overview in proposal.json. Explain this script's purpose, inputs, check mode and output generation. Answer what --check verifies and when Graphviz is invoked. Use genuine returned source references for the claims. Preserve the proposal's operation reference and leave unsupported behavior explicit. Keep other sections as gaps.

The agent writes the prose; Clew retains the source and checks the proposal structure. Read the paragraph yourself and open one of its evidence references before submitting.

4. Ask a question against the saved source

python3 -I -S architecture/examples/first-document.py read \
  --root ./architecture --service cli-documentation \
  --snapshot RETURNED_SNAPSHOT \
  --question "What does --check verify, and when does this script invoke Graphviz?"

Give the returned packet to your agent. Ask for an answer with exact source references and inspect the source behind it. Read mode uses the saved snapshot; it performs no new capture or publication. A subsequent source edit does not change the answer's snapshot.

The recorded answer: verify checks the pinned revision, source and fragment digests, text, line ranges, URLs and graph references. --check then compares saved DOT and Mermaid, parses SVG XML, checks that SVG and claims appear in the saved HTML, and returns without Graphviz or writes. Generation calls dot -Tsvg through render_svg. Read the answer and exact source citations.

The observed read performed no new acquisition or publication and left the existing reader unchanged. This source explanation does not establish that a real generator run passed or that the diagram proves runtime behavior.
